# Refining Task Docs

For each clean/path gate and continuation below and in child briefs, use the four ordinary Git commands and identity checks in [checkout state](../independent-review/references/checkout-state.md#direct-use-preflight), with process-local `GIT_OPTIONAL_LOCKS=0`, actual exits and raw output files. These are own-paths gates over every document of the run; unrelated staged or unstaged paths pass and stay untouched. A separate project checkout owns no document path. A clean gate requires successful commands and empty status and diffs; path gates parse NUL-delimited status and compare exact repository-relative paths, including both rename paths. Failed or unavailable Git evidence stops the dependent action. Use ordinary Git for other read-only checks, retaining real exits. Evidence has the reference's ignored/untracked-content, Git flags/normalization, nested-repository and transient-write limits. Stage/commit only owned paths; write, merge and push authority stays explicit.


`refining-task-docs <spec|plan> [<plan|spec>] [--run window|inline|subagent|background] [--agent claude|codex] [--model M|cli-default] [--effort E|cli-default] [--reviewer-run background|window] [--reviewer-model M|cli-default] [--reviewer-effort E|cli-default] [--reviewer-agent claude|codex] [--reviewer-dual] [--auto]`

One task per run. The refiner owns the review, its fixes and the review marks, and `--run` places it ([Launch](#launch)). By default it is a child in a `window`, a visible session where it talks to the user; a child in a `subagent` or `background` asks every question through the root; under `inline` this session is the refiner. In every place its reviewer is a separate agent in the `--reviewer-run` place. The root resolves the documents, runs the refiner in the project checkout, waits, verifies Git/status facts and reports paths. Outside `inline` it writes no document or mark and never edits a child status. It invokes no other task skill: the user chooses what runs next. A stop placed "before any window" below comes, in every place, before the refiner starts.

Under `--auto` read child-sessions' [auto.md](../child-sessions/references/auto.md): the brief says `Auto: yes`, so the refiner runs its review loop with `--auto` and asks nobody, in its window either, and each question it cannot settle by auto.md's [Deciding](../child-sessions/references/auto.md#deciding) step 1 reaches the root as `STATUS: blocked`; the root routes it and every question below that would go to the user by auto.md's Deciding, and the report lists `## Decisions`.

## Phases

A session performs Prepare, Wait and Accept in order as one root. A session whose brief or prompt carries `Phase: prepare` or `Phase: accept` performs that phase alone and ends as that brief says, naming the record's path. Without a `Phase:` line, continue from Launch to Wait and Events yourself; do not end after Prepare. `--run inline` follows Inline instead, with no phases or record.

| Phase | Who performs it | Sections to read and perform | References to read |
|---|---|---|---|
| Prepare | The single root, or the Prepare agent | Input, Preflight, Brief, Launch | The Prepare list below |
| Wait | The single root, or the phase agents' caller | Wait | child-sessions SKILL.md Wait and Dialogs; launch-settings Child settings check and Places for a subagent first status |
| Accept | The single root, or the Accept agent | Events, Verify, Report | The Accept list below |

Read each phase's references when reaching that phase. Prepare alone launches a `window` worker (open, Startup, early settings check); for `subagent` or `background` it starts nothing, writes `Action: start` and ends. Accept alone ends after a return to the worker or a reopen, writing Waiting (a non-window return as `Action: continue`) instead of waiting. Prepare alone starts no non-window worker, so it does not apply Preflight's refusal for this session being itself a subagent: judge that combination for the caller, which is never a subagent because both orchestrators refuse `--run subagent`; a worker start the host refuses is `launch failure`. Every other refusal stays Prepare's, including an implementer subagent that would itself start subagents.

A phase continuing from a record (`State: … asked …`, the same `Run:` and brief) takes that run's live window and runtime files as its own. Continue at the recorded question with the answer in your context; do not write a new brief or open a second worker. Preflight's live-window refusal and leftover renaming apply only to a new run.

Use the [handoff record format](../child-sessions/references/handoff-record.md#format) and its [Authority rule](../child-sessions/references/handoff-record.md#authority). Read the record before continuing a phase. At an Accept event, read it, the status file's exact first line, then `alive` for a window (the child/producer completion evidence otherwise) before other event evidence; never act on the event's wording. Then check the brief's labelled lines and the record's Authority checks. Read no worker brief prose or input document during Accept.

**Prepare reads:** [task document paths](../planning-task-docs/references/document-paths.md); [review-mark.md](references/review-mark.md) Freshness and the native freshness recipe for this shell, not Marking procedure; [refiner-brief.md](references/refiner-brief.md); checkout-state Direct-use preflight; child-sessions SKILL.md Run places, Locate and open, Dialogs, Other operations and environment, and its brief-writing.md; launch-settings Roles, Precedence, CLI-defaults opt-out, Resolution, Record, Child settings check, Places; run-contract Refused combinations, Earlier runs and Host mechanisms, plus Launch and wait, Permissions and Settings under `subagent` or `background`; handoff-record.md; auto.md under `--auto`. Read documents only as Input describes.

**Accept reads:** the record, worker brief's labelled lines, status file, child-sessions status-file.md and handoff-record.md; launch-settings Child settings check and Places; checkout-state Direct-use preflight; review-mark.md Freshness and this shell's native recipe for Verify 5; child-sessions Locate and open (Startup), Dialogs and Recover a silent exit only for a reopen or a `send`; run-contract Questions and continuation under `subagent` or `background`; auto.md under `--auto`. Accept reads no document through, refiner-brief.md, stages-section.md or document-paths.md; it resolves no launch settings again.

Extract the worker brief's identity lines with this anchored label list: `^(Checkout|Docs repository|Base SHA|Agent|Place|Auto|Launch settings|Reviewer settings|Reviewer run|Reviewer agent|Window name|Documents to review|Context documents|Review mark rules|Stage convention|Git checks|Status file|Opened): `. Keep each matching line's value as written. In review-mark.md Native freshness recipes, select the common preamble and only the current shell's fenced recipe (Bash or PowerShell).

**Facts for this skill:** `Docs repository HEAD at start: <base-sha>`, a copy of the worker brief's `Base SHA:` to compare before using it. Other run values remain on the worker brief's labelled lines.

## Input

1. The project checkout is the top level of the current repository. When that top level is a separate docs repository (a `docs/superpowers` directory with its own repository), the project checkout is `git -C <docs-top>/../.. rev-parse --show-toplevel`; when that fails, ask the user for the project checkout (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)). Project-relative paths such as `**Spec:**` headers resolve against the project checkout, never the docs repository. Resolve applicable project rules. Resolve each given path to an absolute path without reading it through: recognise its kind and pairing by name, place and line searches for `> **For agentic workers:** REQUIRED SUB-SKILL:`, `**Spec:**` and `**Stage:**`; read the last line and run the Freshness native recipe for its mark. Before any document is classified, refuse the reviewer key shapes of Preflight 2 (an invalid `--reviewer-agent` value, `--reviewer-agent` with `--reviewer-dual`, `--reviewer-dual` with any `--reviewer-model`), naming the key and its value, so that a run ending in `nothing to review` below still reports an offending key. Recognise it by [task document paths](../planning-task-docs/references/document-paths.md):
   - **Plan**: a plan by that reference; follow-ups and tails are refused.
   - **Spec**: a spec by that reference.

   Anything else is refused before any window: only specs and plans are reviewed. Two plans or two specs are refused too.
2. A single plan: find its spec by the matching rules; a single spec is reviewed alone, its plans are not added. Matching rules, in order:
   1. Plan to spec in task document paths: same-directory, mirrored naming pair, then `**Spec:**` header.
   2. Else ask the user which spec belongs to the plan. Never guess a pairing. Under `--auto` the question is routed by [auto.md](../child-sessions/references/auto.md#deciding), and no session answers it by guessing: without a task or document of its own that names the spec, it reaches the user.
3. Docs repository = `git -C <document-dir> rev-parse --show-toplevel`; every document of the run must lie in the same one. Run the own-paths gate on the docs repository over every document of the run, those to review and the context documents alike; a hit stops, naming the path. Record the docs repository's full HEAD as `<base-sha>`.
4. Classify each document fresh or stale per [review-mark.md](references/review-mark.md#freshness), `rel` relative to the docs repository, and show each to the user: fresh with verdict, reviewer and date; stale with the failing condition. Stale documents are the documents to review; fresh ones are context only. None stale: report "nothing to review" with each document's mark and stop; no window opens.

## Preflight

1. Decide the place and the agent. The place is `--run`: `window` when absent, also under `--auto`, else `inline`, `subagent` or `background`; the user's words choosing a place count as the key, and any other value stops. Announce a place other than `window`. Select `--agent`, otherwise identify the root's own system from session identity as independent-review's [Session system](../independent-review/SKILL.md#session-system) does; unknown identity requires clarification (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)). Never infer the agent from executable availability, environment, directory names or model. Refuse before anything starts, naming the combination, what run contract [Refused combinations](../child-sessions/references/run-contract.md#refused-combinations) refuses for the refiner: under `inline`, an `--agent` naming a system other than this session's or an explicit `--model` or `--effort`, refused before any edit; under `subagent`, an `--agent` naming a system other than this session's, or this session being itself a subagent on a host whose subagents cannot start subagents; and `--reviewer-run subagent` in every place, naming `background` and `window`: a native subagent has no native review command. A `subagent` or `background` refiner with `--reviewer-run window` opens that reviewer window itself and so waits on child-sessions' present loop, which run contract [Host mechanisms](../child-sessions/references/run-contract.md#host-mechanisms) does not record as verified; the report names it unverified when the run uses it; carry that fact into the record's Report carries when the brief is written.
2. Under `inline` resolve no refiner settings: the refiner is this session ([launch settings Places](../independent-review/references/launch-settings.md#places)). Otherwise resolve the refiner's settings per [launch settings](../independent-review/references/launch-settings.md#precedence) for the selected agent: `--model`/`--effort` are explicit values, `cli-default` is a per-field [opt-out](../independent-review/references/launch-settings.md#cli-defaults-opt-out), and every other field takes the refiner role default. An unresolved or unsupported pair stops before any window. Under `subagent` and `background`, resolve and pass the pair as launch settings [Places](../independent-review/references/launch-settings.md#places) says for the place; a pair the place cannot select and verify is refused before launch, naming the place and the pair. Resolve the reviewer system, the user's words choosing a reviewer counting as the keys. Refuse before any window, naming the key and its value: `--reviewer-agent` with a value other than `claude` or `codex`; `--reviewer-agent` together with `--reviewer-dual`; `--reviewer-dual` together with any `--reviewer-model`, `cli-default` included (under the dual review `review-fix-loop` asks which reviewer a `--reviewer-model` is for, and no key here says which). The reviewer system is `dual` under `--reviewer-dual`, else the `--reviewer-agent` value, else the system opposite to the refiner's agent; a reviewer of the same system as the refiner is accepted. It fills the brief's `Reviewer agent:` line as `<claude|codex|dual> (explicit)` when a key or the user's words set it, else `(default)`. Validate explicit `--reviewer-model`/`--reviewer-effort` values for that reviewer system (effort `low` for a Claude reviewer is unsupported, naming `medium`; under `dual` the effort is validated for both systems, so `low` is refused, naming `medium`): a model of another system or an unsupported pair stops before any window, naming the value and the reviewer system; `cli-default` is accepted. These values fill the brief's Reviewer settings line; without them it says `reviewer policy`. `--reviewer-run <place>` fills the brief's Reviewer run line as `<place> (explicit)`; without it the line says `background (default)`. A place other than `background` or `window` stops before any window.
3. Outside `inline`, locate the installed `child-sessions/SKILL.md`; read its Run places, Locate and open, Dialogs and Other operations and environment sections and brief-writing.md. Prepare names status-file.md in the brief but leaves reading that contract to the worker and Accept. Read launch-settings' Roles, Precedence, CLI-defaults opt-out, Resolution, Record, Child settings check and Places; run-contract's Refused combinations, Earlier runs and Host mechanisms, and under `subagent` and `background` its Launch and wait, Permissions and Settings sections. Resolve its installed platform entrypoint by absolute path (Bash `scripts/child-session`; native Windows `scripts/child-session.ps1` through the installed PowerShell vector in its platform reference). Its command/status contract governs every call. Set `<runtime>` from its successful `runtime-dir` output, outside Git.
4. Check the selected child's actual installed catalogs, this session's own under `inline` (Claude: `~/.claude/skills`, enabled `~/.claude/plugins`; Codex: `~/.codex/skills`, `~/.agents/skills`, enabled `~/.codex/plugins`; plus the project's `.claude/skills` and `.agents/skills`). Resolve readable absolute SKILL.md paths for `review-fix-loop` and `independent-review`, and for `child-sessions` when the Reviewer run place is `window`, since the refiner opens that reviewer window itself. Executables or the root's catalog alone do not prove child skill availability. Missing ones stop before any window; report them for the user to install, without substitution.
5. Names: `<stem>` is the plan's stem when the run has a plan, else the spec's, with every character outside `[A-Za-z0-9_-]` replaced by `-`. Outside `inline`: window `refine-<stem>`, brief `<runtime>/refine-<stem>-brief.md`, status `<runtime>/refine-<stem>-status.md`, handoff record `<runtime>/refine-<stem>-handoff.md`, and for `background` run directories `<runtime>/refine-<stem>-run-<n>`. For a new run only, a live window of that name (`alive refine-<stem>` returns 0) is refused, naming it. Leftover runtime files of that name from an earlier run (brief, status, handoff record, their archived `-blocked-<n>` and `-rejected-<n>` copies, and run directories) are renamed, for a new run only, to `<file>-old-<n>`, `n` the smallest unused number, after the check of run contract [Earlier runs](../child-sessions/references/run-contract.md#earlier-runs); no file exists at the status path when the brief is written.

## Brief

Outside `inline`, fill [refiner-brief.md](references/refiner-brief.md) with absolute resolved paths, the place of Preflight 1 and `Auto:` (`yes` under `--auto`), following child-sessions' brief checklist, and write it to the brief path. `Stage convention:` names this skill's [display copy](references/stages-section.md) of the stage convention. Immediately after writing the brief, create the handoff record with `State: prepare: brief written`, its identity and Facts lines, and any Report carries or Decisions already made.

A `window` brief's `Terminal controls:` line is the template's fixed text: the brief is written before `open`, when no launch exists to report a backend or controls. After every `open` (the first, a reopen, a resume), read that launch's `capabilities <name>` and check its checkout/launch identity before any terminal control; every `peek`, `send` and `key` below is conditional on the current launch's supported capability, never on the brief, and nothing about controls is written into the brief or sent to the child. When the current launch's record lacks `peek`, `send` or `key`, read Told the user and, unless its notice for this launch is already there, tell the user that questions/dialogs need direct attention in that window and append `<launch>: terminal controls unavailable, direct attention` to Told the user, then continue through brief/status files; report dialog counts as not observable. A known `blocked` question still follows the status contract, with its answer entered directly by the user when `send` is unavailable. Under `--auto` the root still decides that answer by [auto.md](../child-sessions/references/auto.md#deciding) and records it; the user is asked only to type that given answer into the window, and the report names the missing `send` as the backend's limitation. A timeout alone supplies no question or approval. Check `alive` before any supported input; never reopen a live agent to inject text. Reopen a proven dead launch at most once under the shared budget below. `close` stops only proven owned processes; unavailable window closure leaves a reported retained window, whose shell alone is not a live agent.

## Launch

Run the refiner in the place Preflight 1 decided.

### Window

1. Append the `Opened:` line of the [child settings check](../independent-review/references/launch-settings.md#child-settings-check) to the brief, then call `open --agent <agent> [--model M] [--effort E] --split right refine-<stem> <project checkout> <brief>`, quoting paths, passing the brief's recorded Launch settings as `--model` and `--effort` and omitting a field that is `cli-default`. The user answers the child's questions in its window (under `--auto`, only watches it), so it asks for a pane right of the root; when `open` prints a fallback note (a tab or a tmux window instead), tell the user where the window opened. The child works in the project checkout: no worktree, no branch of its own. Tell the user that the run owns the task's documents: edit none of them while the window is open; other files stay theirs to change and commit, except that any edit in the docs repository while a reviewer runs makes the child's review loop report `checkout changed`.
2. Read this launch's capabilities and perform child-sessions' Locate and open **Startup**. After Startup (after `open` without `peek`) and before the first long wait, run the early [child settings check](../independent-review/references/launch-settings.md#child-settings-check) and record this opening and its outcome. Only a mismatch stops for the user's continue-or-stop question (under `--auto`, routed by auto.md's Deciding): write `State: prepare: asked settings mismatch`, retaining the window. An answer counts only by the record's Authority rule.

### Subagent and background

For Prepare alone, do not start this worker: record the start recipe below as `Action: start <place>` in Waiting, with the brief, checkout, settings and permission arguments, then complete Launch Record and end. The caller records the actual opening and performs the start; a single root performs it here.

1. Append the `Opened:` line of the [child settings check](../independent-review/references/launch-settings.md#child-settings-check) to the brief, then start the refiner in the project checkout by run contract [Launch and wait](../child-sessions/references/run-contract.md#launch-and-wait): a `subagent` with the pair Preflight 2 resolved, set by the host's native controls; a `background` CLI with the brief's recorded Launch settings, omitting a field that is `cli-default`, and the permission arguments of run contract [Permissions](../child-sessions/references/run-contract.md#permissions), since the refiner writes and commits. Each `background` start or resume writes its run directory at `<runtime>/refine-<stem>-run-<n>`, `n` the smallest unused number. Tell the user that the run owns the task's documents until it reports, as Launch Window 1 words it. The child works in the project checkout: no worktree, no branch of its own.
2. For `background`, run the early child settings check after each start and before waiting; only a mismatch stops for the user's continue-or-stop question, routed by auto.md under `--auto`, and recorded as `State: prepare: asked settings mismatch`. For `subagent`, the early check runs at the first status of each opening (Wait for `blocked`, Events otherwise).

### Record

Complete the [record](../child-sessions/references/handoff-record.md#format): `State: prepare: launched`, every actual opening and early-check outcome, Facts, Report carries, Decisions and Told the user. Before the ownership notice in Launch Window 1 or Subagent and background 1, check Told the user; give it once and record `documents owned by the run`. Carry launch fallback/place notices and dialog counts too. Waiting lists the worker and `Action: none` after an actual start, or the phase-alone non-window start recipe. Prepare alone ends as its brief says, naming the record; a single root continues to Wait.

## Wait

The single root holds the wait; for phase-alone agents their caller holds it. Follow child-sessions' [Wait](../child-sessions/SKILL.md#wait) for `refine-<stem>`, using the rung it proves or its present loop with the host-specific duration, explicit tool timeout and same-command polling. When choosing the rung, write its report line to the record's `Wait:` and set `State: waiting`. For `subagent` and `background`, wait as run-contract Launch and wait says; complete background recording before reading terminal status.


Before handling a `subagent` opening's first `blocked` status, the wait holder runs the early [child settings check](../independent-review/references/launch-settings.md#child-settings-check) and records its outcome in that opening's Openings entry. A mismatch stops before showing/answering Questions, archiving the status or continuing the child; use Launch's continue-or-stop question, auto.md routing and the record's Authority rule. An early check already completed and recorded for this opening is not repeated when a later status reaches Events; Verify's final check still applies.

The wait holder handles these events without starting Accept:

- **`blocked`:** show Questions verbatim with its options and recommendation and obtain the user's answer (under `--auto`, route it by auto.md's Deciding; without `send` the user only types it in, as Brief says). Archive the status to `<file>-blocked-<n>`. For a window, apply Events **Before every send**, send one line or an absolute answer-file instruction, then wait for a fresh status. A dead worker before that send goes to Events **Reopen**, carrying the line to send. For `subagent` or `background`, continue the same child by run-contract Questions and continuation, or its fresh-child fallback with a new `Opened:` line; update Openings and Waiting, then wait again.
- **`124` or `4`:** `peek refine-<stem> 40` when supported; wait again for work in progress, handle a dialog per child-sessions Dialogs, or apply Wait's stall rule and re-arm. Preserve the rung and one-watcher rule. A timeout supplies no question or approval.

Everything else goes to Events. Other command errors stop with artifacts preserved. Keep changed facts, Report carries, Decisions and one-time notices in the record.

## Events

Accept starts from evidence: read the record, the status file's exact first line, then `alive refine-<stem>` for a window (the child/producer completion evidence otherwise). Then validate the record against the brief's labelled lines and runtime evidence by its Authority rule, even when the caller supplied an event description. For a `subagent` whose first status reaches Events, run and record its early child settings check before dispatch, with the same mismatch question and Authority rule as Launch. Use an early check already completed in Wait for that opening instead of repeating it.

- **`done`:** proceed to Verify.
- **`failed`:** show the failure and stop, keeping the window/status or status/run directories; go to Report.
- **Silent exit:** the window worker is gone or the child ended, with no valid first status line. Follow Reopen below. A launch failure gets no restart: stop with its diagnostics and artifacts preserved.
- **`blocked`, a deadline or a stall:** handled by Wait, not as successful completion.

For **Accept alone**, the caller may report three further events. `Event: deadline`: take the evidence above first; a valid status takes its own row, and `alive` exit `1` is Silent exit. A live worker without a status adds `<launch>: no status at the wait's deadline, still working` to Report carries, leaves Waiting as it is and ends `waiting`. `Event: dead before send`: apply Before every send's dead branch with the phase brief's `Line to send:`, then end `waiting` after a successful reopen; its existing stop still applies when the shared reopen is spent. `Event: launch failure`: stop by this skill's launch-failure rule with the phase brief's Diagnostics, preserve the artifacts and end `failed`.

**Reopen.** Read `Reopen:` from the record. With `unused`, for a window `peek refine-<stem> 40` when supported and show diagnostics. Append this continuation line to the brief:

> Continue from the current state of the checkout: read git log and record the ordinary Git evidence and verify checkout/branch/HEAD first. Uncommitted changes on your owned paths are your earlier session's work: inspect them and continue from them.

Close the stale owned window if present, confirm the worker is dead, append a new `Opened:` line, then `open` as Launch Window 1 with the brief's recorded Launch settings, never re-resolved. Run Startup and the early settings check for the new opening, updating Openings. Record `Reopen: used at <Opened time>: silent exit` (or `dead before send` below) and `State: accept: reopened`, including those facts before any settings question. A second silent exit (`Reopen: used …`) stops, keeping the window, status and runtime files. For `subagent` or `background`, use run-contract Questions and continuation's one restart, counted on the same `Reopen:` line; preserve producer exits, stderr and run directories. A phase-alone Accept writes the non-window continuation recipe for the caller instead of starting or continuing the child itself.

**Before every send.** For a `blocked` answer or Verify's mismatch line, run `alive refine-<stem>` first: a dead agent leaves a shell that would run the text. Never reopen a live agent to inject text. If dead and Reopen is unused, close it, append the continuation line above and then the line meant for `send` to the brief, add a new `Opened:` and reopen with recorded settings; run Startup and the early check, update Openings and record `Reopen: used at <Opened time>: dead before send`. This is the same one reopen, shared with a silent exit. If used, stop and report with runtime files retained. Capability checks in Brief govern every terminal control.

**Return to the worker.** Verify's ordinary mismatch may return once while `Return to worker: unused`. Archive as Verify says, record `Return to worker: used: <archived status path>` and `State: accept: returned to worker`, and deliver its mismatch line through Before every send or run-contract Questions and continuation. A repeated mismatch (`Return to worker: used …`) goes to the user, with status and window retained. A settings acceptance or other answer comes only from this session's own conversation or the phase-alone prompt, never the record.

After a reopen or return, rewrite [Waiting](../child-sessions/references/handoff-record.md#waiting): window `Action: none`; a non-window phase-alone continuation `Action: continue <place>` with the recorded session ID, message, brief, checkout, settings and permission arguments. A single root continues to Wait; Accept alone ends as its brief says, naming the record, and waits for nothing. New non-window children receive an actual `Opened:` at their start; the wait holder updates the record and runs the due early check.

## Verify

On `done` outside `inline`, read the expected paths, repository, recorded base HEAD and settings from the worker brief's labelled lines, and the input hash or other retained Facts from the record. Compare the brief's `Base SHA:` to Facts' `Docs repository HEAD at start:` first; a disagreement stops. Under `inline`, use Input's recorded values in this session instead of a brief or record. All of these must hold:

1. Full status format with `## Artifacts`; BRANCH, CHECKOUT and HEAD name the docs repository's current branch, top level and full HEAD.
2. Commits lists the child's own commits in the docs repository: each is in `<Base SHA from the brief>..HEAD` and changes only Artifacts paths (`git show --name-only --format= --no-renames <sha>`, relative to the docs repository). Every other commit of that range is the user's parallel work and changes neither an Artifacts path nor any document of the run, context documents included; one that does stops Verify and goes to the user, naming the commit, never back to the child. A project checkout that is another repository may move freely.
3. A fresh own-paths gate on the docs repository over the Artifacts paths and every document of the run, context documents included, passes: no owned document is left uncommitted.
4. Review gives final refine mode `CLEAN` or `CLEAN EXCEPT DISPUTED`, with the derived reviewer verdict reported separately; dispute-only closure can keep a derived `CHANGES`, never relabelled CLEAN.
5. Every document to review is under Artifacts, and every Artifacts path lies in the docs repository and passes the freshness check of review-mark.md, run by the root.
6. The final [child settings check](../independent-review/references/launch-settings.md#child-settings-check) over every opening in the record's Openings and the brief's `Opened:` lines matches, or the user accepted its result by the record's Authority rule.

A settings mismatch or `settings unverified: <reason>` never goes back to the child: show expected and observed values and the record paths, and ask the user to accept the result with the observed settings or stop with everything preserved (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)). A user commit changing a document of the run goes to the user per Verify 2.
