Use when task documents should be reviewed and fixed before execution, or when a document's Review mark is missing or stale.

# Refining Task Docs

For each clean/path gate and continuation below and in child briefs, use the four ordinary Git commands and identity checks in [checkout state](../independent-review/references/checkout-state.md#direct-use-preflight), with process-local `GIT_OPTIONAL_LOCKS=0`, actual exits and raw output files. These are own-paths gates over every document of the run; unrelated staged or unstaged paths pass and stay untouched. A separate project checkout owns no document path. A clean gate requires successful commands and empty status and diffs; path gates parse NUL-delimited status and compare exact repository-relative paths, including both rename paths. Failed or unavailable Git evidence stops the dependent action. Use ordinary Git for other read-only checks, retaining real exits. Evidence has the reference's ignored/untracked-content, Git flags/normalization, nested-repository and transient-write limits. Stage/commit only owned paths; write, merge and push authority stays explicit.


`refining-task-docs <spec|plan> [<plan|spec>] [--run window|inline|subagent|background] [--agent claude|codex] [--model M|cli-default] [--effort E|cli-default] [--reviewer-run background|subagent|window] [--reviewer-model M|cli-default] [--reviewer-effort E|cli-default]`

One task per run. The refiner owns the review, its fixes and the review marks, and `--run` places it ([Run](#run)). By default it is a child in a `window`, a visible session where it talks to the user; a child in a `subagent` or `background` asks every question through the root; under `inline` this session is the refiner. In every place its reviewer is a separate agent in the `--reviewer-run` place. The root resolves the documents, runs the refiner in the project checkout, waits, verifies Git/status facts and reports paths. Outside `inline` it writes no document or mark and never edits a child status. It invokes no other task skill: the user chooses what runs next. A stop placed "before any window" below comes, in every place, before the refiner starts.

## Input

1. The project checkout is the top level of the current repository. When that top level is a separate docs repository (a `docs/superpowers` directory with its own repository), the project checkout is `git -C <docs-top>/../.. rev-parse --show-toplevel`; when that fails, ask the user for the project checkout. Project-relative paths such as `**Spec:**` headers resolve against the project checkout, never the docs repository. Resolve applicable project rules. Resolve each given path to an absolute path, read it completely and recognise it:
   - **Plan**: it carries the superpowers plan header (`> **For agentic workers:** REQUIRED SUB-SKILL:`) or lies in a `plans/` directory of a superpowers docs dir (`docs/superpowers/plans/`) and is not a `*-follow-ups.md` or `*-tails.md` file.
   - **Spec**: named `*-design.md` or lying in a `specs/` directory.

   Anything else is refused before any window: only specs and plans are reviewed. Two plans or two specs are refused too.
2. A single plan: find its spec by the matching rules; a single spec is reviewed alone, its plans are not added. Matching rules, in order:
   1. Naming pair: `specs/YYYY-MM-DD-<slug>-design.md` with `plans/YYYY-MM-DD-<slug>.md` in the same docs dir.
   2. Else the plan's `**Spec:**` header line (path relative to the project checkout).
   3. Else ask the user which spec belongs to the plan. Never guess a pairing.
3. Docs repository = `git -C <document-dir> rev-parse --show-toplevel`; every document of the run must lie in the same one. Run the own-paths gate on the docs repository over every document of the run, those to review and the context documents alike; a hit stops, naming the path. Record the docs repository's full HEAD as `<base-sha>`.
4. Classify each document fresh or stale per [review-mark.md](references/review-mark.md#freshness), `rel` relative to the docs repository, and show each to the user: fresh with verdict, reviewer and date; stale with the failing condition. Stale documents are the documents to review; fresh ones are context only. None stale: report "nothing to review" with each document's mark and stop; no window opens.

## Preflight

1. Decide the place and the agent. The place is `--run`: `window` when absent, also under `--auto`, else `inline`, `subagent` or `background`; the user's words choosing a place count as the key, and any other value stops. Announce a place other than `window`. Select `--agent`, otherwise identify the root's own system from session identity as independent-review's [Session system](../independent-review/SKILL.md#session-system) does; unknown identity requires clarification. Never infer the agent from executable availability, environment, directory names or model. Refuse before anything starts, naming the combination, what run contract [Refused combinations](../child-sessions/references/run-contract.md#refused-combinations) refuses for the refiner: under `inline`, an `--agent` naming a system other than this session's or an explicit `--model` or `--effort`, refused before any edit; under `subagent`, an `--agent` naming a system other than this session's, or this session being itself a subagent on a host whose subagents cannot start subagents; and with `--reviewer-run subagent` under `subagent`, a reviewer the refiner's subagent cannot start, checked by that item as for a session one level deeper than this one.
2. Under `inline` resolve no refiner settings: the refiner is this session ([launch settings Places](../independent-review/references/launch-settings.md#places)). Otherwise resolve the refiner's settings per [launch settings](../independent-review/references/launch-settings.md#precedence) for the selected agent: `--model`/`--effort` are explicit values, `cli-default` is a per-field [opt-out](../independent-review/references/launch-settings.md#cli-defaults-opt-out), and every other field takes the refiner role default. An unresolved or unsupported pair stops before any window. Under `subagent` and `background`, resolve and pass the pair as launch settings [Places](../independent-review/references/launch-settings.md#places) says for the place; a pair the place cannot select and verify is refused before launch, naming the place and the pair. Validate explicit `--reviewer-model`/`--reviewer-effort` values for the reviewer system the place resolves, the refiner's own system under `--reviewer-run subagent`, otherwise the system opposite to the refiner's agent: a model of another system or an unsupported pair stops before any window, naming the value and the reviewer system; `cli-default` is accepted. These values fill the brief's Reviewer settings line; without them it says `reviewer policy`. `--reviewer-run <place>` fills the brief's Reviewer run line as `<place> (explicit)`; without it the line says `background (default)`. A place other than `background`, `subagent` or `window` stops before any window.
3. Outside `inline`, locate the installed `child-sessions/SKILL.md`; read it, its `references/brief-writing.md` and `references/status-file.md`, and under `subagent` and `background` its `references/run-contract.md`, which governs their launch, wait, questions and permissions. Resolve its installed platform entrypoint by absolute path (Bash `scripts/child-session`; native Windows `scripts/child-session.ps1` through the installed PowerShell vector in its platform reference). Its command/status contract governs every call. Set `<runtime>` from its successful `runtime-dir` output, outside Git.
4. Check the selected child's actual installed catalogs, this session's own under `inline` (Claude: `~/.claude/skills`, enabled `~/.claude/plugins`; Codex: `~/.codex/skills`, `~/.agents/skills`, enabled `~/.codex/plugins`; plus the project's `.claude/skills` and `.agents/skills`). Resolve readable absolute SKILL.md paths for `review-fix-loop` and `independent-review`, and for `child-sessions` when the Reviewer run place is `window`, since the refiner opens that reviewer window itself. Executables or the root's catalog alone do not prove child skill availability. Missing ones stop before any window; report them for the user to install, without substitution.
5. Names: `<stem>` is the plan's stem when the run has a plan, else the spec's, with every character outside `[A-Za-z0-9_-]` replaced by `-`. Outside `inline`: window `refine-<stem>`, brief `<runtime>/refine-<stem>-brief.md`, status `<runtime>/refine-<stem>-status.md`, and for `background` run directories `<runtime>/refine-<stem>-run-<n>`. A live window of that name (`alive refine-<stem>` returns 0) is refused, naming it. Leftover runtime files of that name from an earlier run (brief, status, their archived `-blocked-<n>` and `-rejected-<n>` copies, and run directories) are renamed to `<file>-old-<n>`, `n` the smallest unused number; no file exists at the status path when the brief is written.

## Brief

Outside `inline`, fill [refiner-brief.md](references/refiner-brief.md) with absolute resolved paths and the place of Preflight 1, following child-sessions' brief checklist, and write it to the brief path. `Stage convention:` names this skill's [display copy](references/stages-section.md) of the stage convention.

A `window` brief's `Terminal controls:` line is the template's fixed text: the brief is written before `open`, when no launch exists to report a backend or controls. After every `open` (the first, a reopen, a resume), read that launch's `capabilities <name>` and check its checkout/launch identity before any terminal control; every `peek`, `send` and `key` below is conditional on the current launch's supported capability, never on the brief, and nothing about controls is written into the brief or sent to the child. When the current launch's record lacks `peek`, `send` or `key`, tell the user once for that launch that questions/dialogs need direct attention in that window, then continue through brief/status files; report dialog counts as not observable. A known `blocked` question still follows the status contract, with its answer entered directly by the user when `send` is unavailable. A timeout alone supplies no question or approval. Check `alive` before any supported input; never reopen a live agent to inject text. Reopen a proven dead launch at most once under the shared budget below. `close` stops only proven owned processes; unavailable window closure leaves a reported retained window, whose shell alone is not a live agent.

## Run

Run the refiner in the place Preflight 1 decided.

### Window

1. Append the `Opened:` line of the [child settings check](../independent-review/references/launch-settings.md#child-settings-check) to the brief, then call `open --agent <agent> [--model M] [--effort E] --split right refine-<stem> <project checkout> <brief>`, quoting paths, passing the brief's recorded Launch settings as `--model` and `--effort` and omitting a field that is `cli-default`. The user answers the child's questions in its window, so it asks for a pane right of the root; when `open` prints a fallback note (a tab or a tmux window instead), tell the user where the window opened. The child works in the project checkout: no worktree, no branch of its own. Tell the user that the run owns the task's documents: edit none of them while the window is open; other files stay theirs to change and commit, except that any edit in the docs repository while a reviewer runs makes the child's review loop report `checkout changed`.
2. Follow child-sessions' foreground loop: `wait refine-<stem> <status> 240` on Codex, `540` on Claude. A Codex tool yield is not a timeout: poll the same returned foreground session in intervals of at most 60 seconds until it exits. At the first `wait` return after each `open`, run the early [child settings check](../independent-review/references/launch-settings.md#child-settings-check) for that opening and keep the matched record path; only a mismatch stops the loop for the user's continue-or-stop question.
3. On exit `0`, read the exact first status line. `done` proceeds to Verify. `blocked` shows Questions, options and recommendation, obtains the user's answer, archives the status to `<file>-blocked-<n>`, sends one line or an absolute answer-file instruction, then waits for a fresh status. `failed` shows the failure and stops, keeping the window and status; go to Report.
4. Exit `3`: `peek refine-<stem> 40`, show diagnostics, append “Continue from the current state of the checkout: read git log and record the ordinary Git evidence and verify checkout/branch/HEAD first. Uncommitted changes on your owned paths are your earlier session's work: inspect them and continue from them.” to the brief, close the stale window if present, append a new `Opened:` line and reopen once with the brief's recorded Launch settings; never re-resolve them. A second silent exit stops, keeping the window and status. Exit `124`: `peek refine-<stem> 40`; wait again for work in progress, or handle a dialog per child-sessions Dialogs. Other errors stop with artifacts preserved.
5. Before every `send` (a `blocked` answer here, a mismatch line in Verify), run `alive refine-<stem>`: a dead agent leaves a shell that would run the text. Dead: `close refine-<stem>`, append the continuation line of step 4 and then the line you meant to send to the brief, append a new `Opened:` line, and `open` again with the brief's recorded Launch settings, never re-resolved; this is the run's one reopen, shared with step 4. When that reopen was already used, stop and report, keeping the window and runtime files.

### Subagent and background

1. Append the `Opened:` line of the [child settings check](../independent-review/references/launch-settings.md#child-settings-check) to the brief, then start the refiner in the project checkout by run contract [Launch and wait](../child-sessions/references/run-contract.md#launch-and-wait): a `subagent` with the pair Preflight 2 resolved, set by the host's native controls; a `background` CLI with the brief's recorded Launch settings, omitting a field that is `cli-default`, and the permission arguments of run contract [Permissions](../child-sessions/references/run-contract.md#permissions), since the refiner writes and commits. Each `background` start or resume writes its run directory at `<runtime>/refine-<stem>-run-<n>`, `n` the smallest unused number. Tell the user that the run owns the task's documents until it reports, as Window step 1 words it. The child works in the project checkout: no worktree, no branch of its own.
2. Wait as that section says. At the first status after each opening, run the early child settings check for that opening as launch settings [Places](../independent-review/references/launch-settings.md#places) says; only a mismatch stops for the user's continue-or-stop question.
3. Read the exact first status line. `done` proceeds to Verify. `blocked`: show the user the Questions section verbatim, with its options and recommendation, and obtain the user's answer; archive the status to `<file>-blocked-<n>`; continue the same child with the answer by run contract [Questions and continuation](../child-sessions/references/run-contract.md#questions-and-continuation), or the fresh child it falls back to, which gets a new `Opened:` line; then wait again. `failed` shows the failure and stops, keeping the status and run directories; go to Report.
4. A child that ends without a valid first status line gets the run contract's one restart; a second such end, or a launch failure, stops as that section says, keeping the checkout, status and run directories.
5. Verify and Report apply as written, except: a mismatch Verify returns to the child continues the same child as a `blocked` answer does (step 3), its one line being the message; each opening's settings record is the one launch settings [Places](../independent-review/references/launch-settings.md#places) names for the place; for `background` the report adds each start's and resume's producer exit and session ID; there is no window to close.

### Inline

This session is the refiner: no child, brief, status file or window.

1. Tell the user that the run owns the task's documents until it reports, as Window step 1 words it. Read the review-fix-loop and independent-review SKILL.md paths Preflight 4 resolved, then perform the Work of [refiner-brief.md](references/refiner-brief.md) with the documents to review and context documents of Input 4, the Reviewer run and Reviewer settings of Preflight 2, the [display copy](references/stages-section.md) of the stage convention and [review-mark.md](references/review-mark.md), and the brief's rules after Work: Boundaries, the Review report's rules and out-of-scope findings. Work in the project checkout, commit in the docs repository, and run `review-fix-loop` yourself, its reviewer a separate agent in the Reviewer run place. Talk to the user directly in this session, the loop's questions included. Where the brief says to write STATUS: blocked or failed, stop and report that to the user.
2. Verify 2–5 hold with the documents this session marked or changed as Artifacts and its own commits as Commits; Verify 1, the status format, and Verify 6, the settings check, do not apply. Correct a mismatch of your own once and verify again; a user commit changing a document of the run goes to the user per Verify 2, and so does a repeated mismatch.
3. Report as Report says, with no window to close; the settings line says `inline: current session` and names this session's system, beside the Reviewer settings and Reviewer run of Preflight 2.

## Verify

On `done`, all of these must hold:

1. Full status format with `## Artifacts`; BRANCH, CHECKOUT and HEAD name the docs repository's current branch, top level and full HEAD.
2. Commits lists the child's own commits in the docs repository: each is in `<base-sha>..HEAD` and changes only Artifacts paths (`git show --name-only --format= --no-renames <sha>`, relative to the docs repository). Every other commit of that range is the user's parallel work and changes neither an Artifacts path nor any document of the run, context documents included; one that does stops Verify and goes to the user, naming the commit, never back to the child. A project checkout that is another repository may move freely.
3. A fresh own-paths gate on the docs repository over the Artifacts paths and every document of the run, context documents included, passes: no owned document is left uncommitted.
4. Review gives final refine mode `CLEAN` or `CLEAN EXCEPT DISPUTED`, with the raw reviewer verdict reported separately; dispute-only closure can keep raw `CHANGES`, never relabelled CLEAN.
5. Every document to review is under Artifacts, and every Artifacts path lies in the docs repository and passes the freshness check of review-mark.md, run by the root.
6. The final [child settings check](../independent-review/references/launch-settings.md#child-settings-check) over every opening's record matches, or the user accepted its result.

A settings mismatch or `settings unverified: <reason>` never goes back to the child: show expected and observed values and the record paths, and ask the user to accept the result with the observed settings or stop with everything preserved. A user commit changing a document of the run goes to the user per Verify 2. Any other mismatch goes back to the child once: archive the status to `<file>-rejected-<n>`, `send` one line naming the mismatch and asking for a fresh report at the same path, wait and verify again. A repeated mismatch goes to the user, with window and status kept.

## Report

Report the final refine mode and the raw reviewer verdict; each document with its new `Review:` line, `fresh, context only` when untouched, or `not marked: <why>`; disputed findings with both positions; the commits; and every Out of scope line. When Verify 3's preflight listed paths other than the owned documents, add `unrelated uncommitted changes left untouched: <count>`, without listing them. Add one settings line: role `refiner`, effective model and effort, source of each, the settings check outcome, and the record paths or the user's acceptance; and the brief's Reviewer settings and Reviewer run lines. Without a clean verdict nothing is marked, and the report says what is left: the documents still unmarked and the open findings the status names. After a verified `done`, `close refine-<stem>`; otherwise the window and status stay for the user.
