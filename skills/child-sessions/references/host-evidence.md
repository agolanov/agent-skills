# Host mechanisms and observed coverage

Initial catalog check on 2026-11-05 used Linux (WSL2), Claude Code 2.1.318 and codex-cli 0.166.0: installed CLI help, live Claude agent schemas, recorded Codex tool lists and existing runtime records; that reading launched nothing. Help means installed help, schema the live tool schema, observed actual retained runtime evidence. Later V2 executed the complete producer/watcher recipes through Bash and native PowerShell 7.6.9 with controlled fake CLIs; failure observations were synthetic. One V3 print-mode Claude coordinator foreground-joined one native agent on Linux/WSL2, which exercised the tmux window waits and the published background watcher over a real wrapper. Both test CLIs were fakes, so this verifies waiting/recording rather than real worker-model launches. Its retained report distinguishes the helper exits, an enclosing diagnostic-shell exit, recording completion and the later host notification, and separately records an unnecessary coordinator metadata-inspection deviation. Installed help and live schemas win over this table. The earlier real background planner used bounded record waits and supplies no acceptance for the new marker recipe. Other hosts/versions/platforms remain unverified. A run may use an `unverified` entry, names it unverified in its report, and falls back as [Questions and continuation](run-contract.md#questions-and-continuation) says. The free-wait rows were observed on 2026-11-11 on Linux/WSL2 with Claude Code 2.1.322 and codex-cli 0.167.0. Unlike other entries, an `unverified` or unlisted host notification gives no rung 1.
