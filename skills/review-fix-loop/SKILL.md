# Review Fix Loop

`review-fix-loop [--codex | --claude | --dual] [--run inline|subagent|background|window] [--model M] [--effort E] [--reviewer-run background|subagent|window] [--reviewer-model M] [--reviewer-effort E] [--auto]`

The loop owner, the implementing session, owns decisions, fixes and the loop. An independent reviewer checks the task. `--run` places the loop owner: `inline`, the default, is this session, which did the work; `subagent`, `background` or `window` move the loop to a child ([Run elsewhere](#run-elsewhere)).

Under `--auto` read child-sessions' [auto.md](../child-sessions/references/auto.md): every question below that would go to the user is routed by its Deciding, every brief and prompt this skill writes says `Auto: yes`, and the report lists `## Decisions`.

## Run elsewhere

Under `--run subagent`, `background` or `window` this session is a thin launcher (run contract [Places](../child-sessions/references/run-contract.md#places)) and runs none of steps 1–5: a child of this session's system performs this skill `inline`, and this session writes its brief, launches it, waits, relays its questions and reports its result. A `--run` value other than the four places stops before anything starts.

1. **Before launch.** Read the installed `child-sessions/SKILL.md`, its `references/brief-writing.md`, `references/status-file.md` and `references/run-contract.md`; resolve its platform entrypoint by absolute path and set `<runtime>` from `runtime-dir`. Refuse, naming the combination, what step 1 refuses before anything starts (judged for the child) and what run contract [Refused combinations](../child-sessions/references/run-contract.md#refused-combinations) refuses for the loop owner's place; under `subagent` that includes `--reviewer-run subagent` on a host whose subagents cannot start subagents, since the child would start it. Resolve the scope as step 1 does: the absolute task checkout and branch, the full fixed task base, the requirements, the task-owned uncommitted paths with the excluded unrelated ones, and the checks; the child has none of this session's history.
2. **Settings.** Resolve the loop owner's settings for role `implementer` per [launch settings](../independent-review/references/launch-settings.md#precedence): `--model`/`--effort` are explicit values, `cli-default` is a per-field [opt-out](../independent-review/references/launch-settings.md#cli-defaults-opt-out), every other field takes the role default; resolve and pass the pair as launch settings [Places](../independent-review/references/launch-settings.md#places) says for the place. An unresolved or unsupported pair, or one the place cannot select and verify, stops before launch, naming the place and the pair.
3. **Brief.** `<slug>` is the task checkout's current branch, or its short HEAD when detached, with every character outside `[A-Za-z0-9_-]` replaced by `-`: window `loop-<slug>`, brief `<runtime>/loop-<slug>-brief.md`, status `<runtime>/loop-<slug>-status.md`, `background` run directories `<runtime>/loop-<slug>-run-<n>`. A live window of that name is refused, naming it; leftover runtime files of that name are renamed `<file>-old-<n>`, `n` the smallest unused number. Write the run contract [brief](../child-sessions/references/run-contract.md#brief): `Skill:` this SKILL.md; `Arguments:` every key given except `--run`, `--model` and `--effort`; `Checkout:` the task checkout; `Authority:` the task-state commit and one fix commit per round on the task branch, nothing more (step 2); `Place:`; `Auto:` `yes` under `--auto`, else `no`; `Status file:`; then the `Launch settings:` line of launch settings [Record](../independent-review/references/launch-settings.md#record). The inputs follow: `Base SHA:` the full fixed task base; `Requirements:` the absolute requirement document paths, or the task text verbatim; `Task paths:` the task-owned uncommitted paths and the excluded unrelated ones, or `None`; `Checks:` the resolved complete-suite and targeted commands with their cwd and source, or `no complete suite defined`, and any unavailable coverage. Tell the child to read the Skill completely and perform it `inline` with the Arguments, within the Authority, taking these inputs as step 1's scope after verifying them against the checkout as step 1 does, and to write its report into the status by status-file.md: `STATUS: done` for `clean` or `clean except disputed`, `STATUS: failed` for `blocked: <reason>`; Review holds the step 5 report (final refine mode beside the raw verdict, rounds and targets, assignment and evidence, decisions, deferred and disputed findings with both positions, findings rejected by cross-check, the squash command), Checks its checks, Commits its commits and Out of scope its outside-scope candidates. In a `window` the child may ask the user there, except under `--auto`; in `subagent` and `background`, and in a `window` under `--auto`, each question ends its turn with `STATUS: blocked` holding the question, options and its recommendation, and every turn ends with the status file written and its exact first line as the child's last message.
4. **Launch and wait.** Append the `Opened:` line, then launch and wait by run contract [Launch and wait](../child-sessions/references/run-contract.md#launch-and-wait): a `window` through child-sessions' `open --agent <this session's system>` with the pair, omitting a `cli-default` field; a `subagent` with the pair set by the host's native controls; a `background` CLI with the pair and the [Permissions](../child-sessions/references/run-contract.md#permissions) arguments, since the child commits. Run the early child settings check at the first status after each opening; only a mismatch stops for the user's continue-or-stop question. A `blocked` status: show its Questions verbatim with options and recommendation, obtain the user's answer and continue by run contract [Questions and continuation](../child-sessions/references/run-contract.md#questions-and-continuation). Under `--auto` the mismatch question and every `blocked` question are routed by [auto.md](../child-sessions/references/auto.md#deciding) instead.
5. **Finish.** After `done` or `failed`, run the final [child settings check](../independent-review/references/launch-settings.md#child-settings-check), then report the child's result as this skill's report: the status's first line, Review, Checks, Commits and Out of scope, one settings line (role `implementer`, effective model and effort with their sources, the check outcome and record paths, or the user's acceptance) and, for `background`, each producer exit and session ID, and under `--auto` the status's `## Decisions` with this session's own. Under `--auto`, when the child ends `clean except disputed` and this session is the first session, apply auto.md's [`CLEAN EXCEPT DISPUTED`](../child-sessions/references/auto.md#deciding) rule to its disputed findings before reporting: read both positions of each, dismiss them, recorded under `## Decisions`, only when it judges none a defect, and otherwise ask the user the fix-or-dismiss question; a launcher that is itself a child leaves the question in its report. After `done`, `close` a window; otherwise it stays with the status for the user.

## Skill composition

Keep normal skill discovery and automatic invocation active in both sessions; read and apply matching skills at each stage. Compose their methods with review-fix-loop's role, scope, verdict, finding evidence, prior dispositions, coverage and checks. Skills that set output style or compress text (for example caveman-review or caveman) never change the format, length or completeness of a report or record this loop or its review prompts require; the required format wins.

## 1. Establish scope and reviewer

Resolve the absolute task checkout (including a worktree used by the implementation), branch, HEAD, fixed task base, requirements and checks. Include branch changes, staged/unstaged task changes and task-owned untracked files; preserve unrelated work and list exclusions. Resolve ambiguous scope first. Resolve exact ordered complete-suite and targeted commands with cwd/source once, following independent-review’s [suite contract](../independent-review/references/checkout-state.md#resolve-checks-and-bind-suite-evidence): approved spec Verification, mandatory project rules/defaults, then README only where needed. Resolve conflicts first and record unavailable coverage or `no complete suite defined`. Forward this set to every prompt.

### Reviewer

Read [independent-review](../independent-review/SKILL.md), using the installed catalog if its sibling is unavailable. Missing: report that `independent-review` is required and stop before review or fixes; do not install or invent the protocol. Resolve the reviewer's assignment by its **Assignment** section, with these keys, before anything starts:

- **System:** `--codex`, `--claude`, `--dual` (Codex and Claude together) or equivalent prose. With none, a resumed loop keeps its recorded system; otherwise the reviewer is the system opposite to the loop owner's, identified as independent-review's [Session system](../independent-review/SKILL.md#session-system) does, or the loop owner's own system when `--reviewer-run subagent` is given.
- **Place:** `--reviewer-run background|subagent|window` or equivalent words, passed to independent-review as its place; default `background`. A resumed loop keeps its recorded place unless `--reviewer-run` is given now, which replaces it, announced and recorded in the loop record. `--reviewer-run inline` is refused: reviewing one's own work is not independent. Independent-review's refused combinations are refused here too: a subagent of another system, `--dual` with `subagent` (the dual assignment takes `background` or `window`), and a subagent inside a subagent on a host that cannot start one.
- **Reviewer settings:** `--reviewer-model` and `--reviewer-effort` set the reviewer, passed as independent-review's `--model` and `--effort`. Under `--dual`, `--reviewer-effort` sets both reviewers' effort and a `--reviewer-model` asks which reviewer it is for (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)); prose may set one reviewer's value, passed as `--codex-model`, `--codex-effort`, `--claude-model` or `--claude-effort`.
- **Loop owner settings:** `--model` and `--effort` set the loop owner. With `--run inline`, the default, the loop owner is this session, so they are refused before anything starts: "the loop owner is this session; use --reviewer-model/--reviewer-effort for the reviewer". In another place they are the loop owner's launch settings, consumed by the launcher ([Run elsewhere](#run-elsewhere)).
- **Removed keys:** `--subagent` (now `--reviewer-run subagent`) and `--reviewer codex|claude` (now `--codex` or `--claude`) are refused before anything starts, naming their replacements.

The `dual` assignment has Codex and Claude review every round through [the dual review](../independent-review/references/dual.md): read it too, and resolve both reviewers' settings by its [step 1](../independent-review/references/dual.md#1-settings-and-target).

Keep one [loop record](references/loop-record.md) outside the checkout; reuse an existing task log. Record the resolved assignment there. Use the explicit round limit, otherwise five completed rounds.

## 2. Commit the reviewed state

Invoking review-fix-loop explicitly requests a task-state commit and one fix commit per round on the task branch, satisfying "commit only when asked" rules. A request that forbids commits, such as "no commits", withdraws that request: do not start this step; stop and ask the user whether to allow the task-state and fix commits or to end without review. Before the first commit, stop on detached HEAD or the default branch (`main`/`master` or configured default) and ask for branch/commit confirmation unless already authorized in the request. Under `--auto` both questions are routed by [auto.md](../child-sessions/references/auto.md#deciding), a commit consent like any other. This authority covers exactly those commits on the task branch; anything else (push, merge, rebase, amend, squash, deploy, worktree creation, installation, persistent configuration changes) needs its own authorization.

Record the pre-loop HEAD for the user's squash command. Commit task-owned staged/unstaged and untracked changes as `review-fix-loop: task state before review` if present. Select exact task paths and commit only them; an ordinary commit of the whole index could absorb unrelated staged work. Preserve unrelated index/worktree changes and record their exclusions and existing status. After each fix batch, run affected checks and make exactly one commit naming the round and finding IDs. Run the complete suite before creating any commit that may become the final reviewed HEAD; when its role is unknown, assume it may. The final-pass reviewer runs the suite again independently. Run the resolved suite again on committed HEAD before review; the pre-commit run is not evidence for the new commit. Bind evidence to commit, checkout, exact commands/cwd/exits and successful Git outputs/comparison per the [suite contract](../independent-review/references/checkout-state.md#resolve-checks-and-bind-suite-evidence). Failed post-commit checks block without authorizing amend, squash or unreviewed corrective commits; resolve within fix authority and remaining budget or report blocked. Every review targets a recorded stable commit.

For the dual assignment, the dual review's [Complete suite](../independent-review/references/dual.md#2-complete-suite) owns suite reuse, writes and evidence refresh. The loop's run replaces both reviewers' suite, final included; the single final reviewer still reruns independently.

## 3. Request independent review

Obtain each attempt from independent-review with the round's target row and order, under `--auto` with `--auto` too, so its prompt says `Auto: yes`. Each round gets a fresh round directory beside the loop record, which holds the round's attempt directories. Give its name a random part (`mktemp -d "<record dir>/round-<n>-XXXXXX"` on POSIX, a random directory name on PowerShell): a window reviewer's name is built from it and must differ from every other loop's. Carry requirements/rules/checks, previous verdict, and the full finding ledger with evidence and disposition basis. Select the target and order:

| Review | Target and order |
| --- | --- |
| Round 1 | Complete task `<base>..HEAD` against original requirements, including security-focused review; no single-reviewer complete-suite rerun. |
| Scoped round | Previous round's single fix commit; verify each accepted fix and its regressions first, then defects introduced by that commit. Keep required prior-finding dispositions. |
| Final pass | Complete task `<base>..HEAD`, prior fixes first; include accumulated outside-round candidates, complete test suite and security-focused review. |
| Disposition round | Same HEAD, ledger dispositions only; confirm them or re-raise with evidence. |

In scoped rounds, defects noticed outside the fix commit are outside-round candidates: without widening this review, record them for the final pass if it is still pending. After that sole pass has run, adjudicate new candidates immediately by evidence; accepted task defects get a fix commit and scoped verification within the remaining limit, other candidates get a recorded disposition. Pre-existing outside-task problems stay separate and never block.

In a dual assignment each review in the table, final pass and disposition rounds included, is one dual review, its resumes included, and that review is one round whatever reviewer and cross-check calls it makes. Pass the dual review (`independent-review --dual`) its recorded place, both recorded settings, the round's target row and order, the full finding ledger with its `Next D` from the [loop record](references/loop-record.md) as the ledger input of its [step 4](../independent-review/references/dual.md#4-matching), the step 2 suite run and the round directory as `<dual dir>`.

## 4. Validate and decide

Each attempt comes back validated by independent-review (its **Validate** section) as `valid`, `invalid: <reason>` or `checkout changed`, with its `result.md`; copy those facts into the round's "Result validity/completion" field. A result not obtained from independent-review on a recorded commit, such as a review taken on uncommitted changes, is an invalid attempt of the pending round and never a completed round.

Apply independent-review’s [Phase recovery and resume](../independent-review/references/checkout-state.md#phase-recovery-and-resume) to suite evidence, single attempts and retries. Failed pre-capture launches nothing/spends no attempt; unavailable post-capture spends the existing budget and retains its pre-phase baseline for recovery comparison. Unavailability alone is not a write. Capture errors persist alongside any proven difference.

Any `checkout changed` result (a moved HEAD, a new or changed file, or an index change) requires adjudication. With the unexpected work and its diff preserved and its source identified by independent-review, pause retries for implementing-session adjudication/reconciliation and affected checks within authority. Unresolved ownership/scope blocks. Do not silently incorporate a reviewer's edit in the fix commit or reset unrelated work. Outcomes:

- A reviewer write to task state, or a moved HEAD, invalidates the attempt.
- A demonstrably unrelated scratch write with required state and coverage intact is recorded without spending a retry.
- Any other invalid attempt spends the shared budget: initial attempt plus one retry per pending round, same assignment; reconciliation or new commits do not reset it. A second invalid attempt blocks.

In a dual assignment the round's result is the dual review's return instead: it validates and retries each reviewer's attempts under its [Budget](../independent-review/references/dual.md#budget), which replaces the loop's per-round budget, and the loop adds no retry of its own. Record the return and its `state.md` facts in the round.

- `<dual dir>/report.md` completes the round. Its derived verdict is the round's verdict wherever steps 4 and 5 read one, the `clean` and `clean except disputed` conditions included, whatever either reviewer's raw verdict; record and report both raw verdicts beside it as given, never relabelled. Adjudicate the report's confirmed findings below (an `unrated` one on its evidence, as accepted or rejected, never deferred) and take its cross-check results as given. Its `Candidates` (outside-round, outside-task, a verifier's noticed-not-verified item) follow step 3 and **Outside-scope** with one difference: no candidate is fixed on this session's own evidence. A candidate is carried in the ledger input of the next dual review, scoped or final, as prior-finding context, where the reviewers may raise it as a finding that goes through matching and cross-check; a candidate that surfaces after the final pass with no further review pending is recorded for the user, not fixed. For the dual assignment this replaces step 3's immediate adjudication of candidates after the final pass.
- `checkout changed: <state.md>`: the caller adjudicates and reconciles under the rules above. An unattributable parallel reviewer write is a reviewer write, not unresolved ownership: choose `invalidating` unless demonstrably unrelated scratch. Resume with `independent-review --dual --resume <state.md> --write scratch|invalidating` per the dual review's [State and resume](../independent-review/references/dual.md#state-and-resume), which owns content restoration, new-commit targets/baselines and spent-attempt continuity.
- `blocked: <codex|claude|codex and claude> invalid result` blocks the round.

Adjudicate every finding in the [record](references/loop-record.md):

- **Accepted:** a critical/important defect or spec-compliance gap requires a fix. A runnable reproduction that demonstrates a violated requirement is accepted after verification, regardless of opinion.
- **Rejected:** give a checkable quoted requirement or test demonstrating correct behavior. An unsupported opinion cannot reject a finding.
- **Deferred:** minor/style findings are fixed cheaply alongside defects or listed for the user. They never start a fix round alone and are not open blocking defects.
- **Disputed:** after a recorded rejection with basis, a reviewer re-raises the same scenario/violated requirement without new evidence. A moved line alone preserves identity; new evidence instead requires fresh evaluation. Record both positions and the fix-or-dismiss question for the user, continue other work and spend no further rounds on that finding. Under `--auto` the question leaves with the report and is settled by auto.md's [`CLEAN EXCEPT DISPUTED`](../child-sessions/references/auto.md#deciding) rule, which belongs to the first session: the loop owner applies it only when it is the first session itself.
- **Outside-scope:** record pre-existing/outside-task candidates once for the final report; outside-round candidates follow step 3.
- **Rejected by cross-check:** in a dual assignment, each finding in the report's `Rejected by cross-check` section, a `repeat` included, is recorded `rejected by cross-check: <verifier evidence>` with its raiser and source ID, and is closed: not fixed, not `disputed`, never blocking `clean`. A later report decides its next state: a repeat changes nothing, a renewed rejection records the re-raise's evidence beside the new verifier evidence, and a confirmation brings it under the rules above.

## 5. Fix, repeat and finish

Fix accepted defects in one round commit, including cheap minor fixes, run affected required checks and request its scoped review. A failed required check (even PASS text with nonzero exit) blocks dependent work; use matching debugging skills, resolve within authority and rerun. Missing dependencies needing broader authority are reported blockers.

A valid round-1 CLEAN can finish immediately if the resolved full suite passes on that commit and required coverage is complete. Required failed/unrun checks prevent either clean mode even when findings are CLEAN. Otherwise, after a scoped CLEAN or a round with no fix commit (all findings rejected/deferred/outside-scope), run the **one final complete pass** if it has not run. Final-pass findings return through ordinary fix-commit/scoped rounds; there is never a second complete pass. If no fix commit exists after the final pass, use at most one disposition round per disposition set on the same HEAD: CLEAN confirms, an evidence-free repeat becomes disputed.

**No progress:** if successive rounds return the same finding set with no accepted fix, stop repeating that unchanged review. Fix confirmed defects now and verify within remaining rounds, or mark eligible evidence-free repeats disputed; an unresolved non-disputed defect blocks rather than silently disappearing.

**Limit:** every valid result counts, including final/disposition passes; invalid attempts never do. At the cap, adjudicate every open finding with a recorded reason. A last small unambiguous fix commit is allowed only when its scoped verification still fits within the limit. Otherwise report `blocked: round limit` with unresolved findings and next action.

Report:

- `clean`: valid CLEAN on final HEAD, required final pass completed when more than one round ran, implementing-session full suite passing on that commit, no unresolved accepted critical/important defects or compliance gaps, and outside-round candidates adjudicated.
- `clean except disputed`: the same coverage, final-pass, commit and check conditions, plus disputed findings with both positions and the fix-or-dismiss question. A substantive final/scoped/disposition `CHANGES` may close in this status when its only remaining blocking claims are evidence-free repeats now adjudicated `disputed`, every other finding is resolved/deferred/outside-scope, and no further required review remains. Preserve the raw `CHANGES` verdict and explain this disposition-based closure; never relabel the reviewer result CLEAN. Deferred minors alone do not qualify for this exception.
- `blocked: <reason>`: exhausted invalid attempts or round limit, failed required checks, missing dependencies, unresolved edit ownership, or unmet completion requirements.

Later task edits invalidate the reviewed result. Report rounds/targets/commits, assignment/evidence, checks, all decisions, deferred/disputed findings and outside-scope candidates, and under `--auto` the `## Decisions` of [auto.md](../child-sessions/references/auto.md#decisions). In a dual assignment also report the findings rejected by cross-check in their own section, each with both positions. Print the user's squash command without executing it; leave round history unsquashed. With no excluded staged work: `git reset --soft <pre-loop HEAD> && git commit`. If unrelated staged changes remain, print `git reset --soft <pre-loop HEAD> && git --literal-pathspecs commit --only -- <exact task paths>` instead, binding and quoting the task paths so the commit preserves excluded staging. `--literal-pathspecs` keeps Git from reading a file name such as `:(glob)…` as pathspec magic.
