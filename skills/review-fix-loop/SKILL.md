# Review Fix Loop

`review-fix-loop [--codex[=<command>] | --claude[=<command>] | --dual] [--run inline|subagent|background|window] [--model M] [--effort E] [--reviewer-run background|window] [--reviewer-model M] [--reviewer-effort E] [--auto]`

The loop owner, the implementing session, owns decisions, fixes and the loop. An independent reviewer checks the task. `--run` places the loop owner: `inline`, the default, is this session, which did the work; `subagent`, `background` or `window` move the loop to a child ([Run elsewhere](#run-elsewhere)).

Under `--auto` read child-sessions' [auto.md](../child-sessions/references/auto.md): every question below that would go to the user is routed by its Deciding, every brief this skill writes and every window driver brief or cross-check prompt of its reviews says `Auto: yes`, and the report lists `## Decisions`.

## Run elsewhere

Under `--run subagent`, `background` or `window` this session is a thin launcher (run contract [Places](../child-sessions/references/run-contract.md#places)) and runs none of steps 1–5: a child of this session's system performs this skill `inline`, and this session writes its brief, launches it, waits, relays its questions and reports its result. A `--run` value other than the four places stops before anything starts.

Follow child-sessions' [Thin launchers](../child-sessions/references/run-contract.md#thin-launchers) with these local parameters.

- **Inputs and refusals.** Resolve step 1's scope: the absolute task checkout and branch, full fixed task base, target form (`range` or `files: <paths>`) and related-code checkout, requirements, task-owned uncommitted paths and excluded unrelated ones, and exact checks. Apply step 1's refusals judged for the child.
- **Worker and arguments.** Role `implementer`, with the effort chosen by launch-settings' [Effort by task](../independent-review/references/launch-settings.md#effort-by-task) from the requirements resolved in step 1's scope, the work the loop owner fixes, and recorded on the brief's `Launch settings:` line with source `policy` and the justifying step as its `effort step:` clause; consume `--run`, `--model` and `--effort`. `Arguments:` holds every other key as given. `Checkout:` is the task checkout.
- **Name.** `loop-<slug>`, where `<slug>` is the task checkout's current branch or its short HEAD when detached, with every character outside `[A-Za-z0-9_-]` replaced by `-`.
- **Authority and brief inputs.** `Authority:` the task-state commit and one fix commit per round on the task branch, nothing more (step 2). Add `Base SHA:` the full fixed task base; `Target:` the recorded target form, `range` or `files: <repository-relative paths>`, and for a document review `Related code: <absolute project checkout>`; `Requirements:` absolute requirement document paths or the task text verbatim; `Task paths:` task-owned uncommitted paths and excluded unrelated ones, or `None`; `Checks:` resolved complete-suite and targeted commands with cwd and source, or `no complete suite defined`, and any unavailable coverage. Tell the child to take these as step 1's scope after verifying them against the checkout as step 1 does.
- **Suite evidence.** Add `Suite evidence:` with the absolute [suite handoff reference](../independent-review/references/checkout-state.md#run-and-hand-off-a-suite), an external records directory and retained suite-record paths (`None` when absent). The child reads it before its first complete suite, inspects retained runs before scheduling another and links actual suite records in `Checks`.
- **Questions and result.** Every question follows the shared window/blocked routing. The child writes `STATUS: done` for `clean` or `clean except disputed`, `STATUS: failed` for `blocked: <reason>`. Review holds the step 5 report: final refine mode beside the last derived verdict, rounds and targets, assignment and evidence, decisions, deferred and disputed findings with both positions, findings rejected by cross-check, and the squash command. Checks holds its checks, the pending merge-candidate checks included, Commits its commits and Out of scope its outside-scope candidates. Report the status's first line, Review, Checks, Commits and Out of scope as this skill's report, with the shared launch evidence.
- **Disputed completion.** Under `--auto`, when the child ends `clean except disputed` and this session is the first session, apply auto.md's [`CLEAN EXCEPT DISPUTED`](../child-sessions/references/auto.md#deciding) rule before reporting: read both positions of each disputed finding; dismiss them, recorded under `## Decisions`, only when this session judges none a defect; otherwise ask the user the fix-or-dismiss question. A launcher that is itself a child leaves the question in its report.

## Skill composition

Keep normal skill discovery and automatic invocation active in both sessions; read and apply matching skills at each stage. Compose their methods with review-fix-loop's role, scope, verdict, finding evidence, prior dispositions, coverage and checks. Skills that set output style or compress text (for example caveman-review or caveman) never change the format, length or completeness of the loop's own records or of a cross-check report; the required format wins. A native review report has the form its tool gives it; the session reads it as [independent-review](../independent-review/SKILL.md#validate) says.

## 1. Establish scope and reviewer

Resolve the absolute task checkout (including a worktree used by the implementation), branch, HEAD, fixed task base, requirements and checks. Include branch changes, staged/unstaged task changes and task-owned untracked files; preserve unrelated work and list exclusions. Select exact requirement-bearing files or sections by independent-review's [Review coverage](../independent-review/SKILL.md#review-coverage). Resolve ambiguous scope first. Record the target form with the scope ([target](../independent-review/references/review-wrapper.md#target)): `range` for a task that is the changes of a commit range, the default; `files: <paths>` when the caller names whole files whose history is no single task range (`refining-task-docs` does, with its documents). The task checkout is the repository holding the task's commits: for a document review the docs repository, with the project checkout recorded as related code. Resolve exact ordered complete-suite and targeted commands with cwd/source, intended coverage and required phase/producer obligations once, following independent-review’s [suite contract](../independent-review/references/checkout-state.md#resolve-checks-and-bind-suite-evidence): approved spec Verification, mandatory project rules/defaults, then README only where needed. Resolve conflicts first and record unavailable coverage or `no complete suite defined`. Inspect retained implementation runs before scheduling checks; record run/acceptance paths and pending requirements. The loop owner resolves and runs the checks; reviewers get the commands and their results as data in their context files.

**Merge-candidate checks.** A [merge-candidate check](../independent-review/references/checkout-state.md#merge-candidate-checks), a required check whose Verification item names the merge candidate as its phase, belongs to the merge, after this loop. Record it with its command as `pending: merge candidate` and give it in that state to every context file. The loop leaves it unrun at entry, in every round and at the final pass, and it holds back neither `clean` nor `clean except disputed`. The session that merges has it run on the merge candidate, the reviewed branch standing on the current main; without such a session it is the user's to run before merging.

### Reviewer

Read [independent-review](../independent-review/SKILL.md), using the installed catalog if its sibling is unavailable. Missing: report that `independent-review` is required and stop before review or fixes; do not install or invent the protocol. Resolve the reviewer's assignment by its **Assignment** section, with these keys, before anything starts:

- **System:** `--codex`, `--claude`, `--dual` (Codex and Claude together) or equivalent prose; `--codex=<command>` and `--claude=<command>` also give the reviewer's launch command, beside `--dual` that reviewer's only, passed to independent-review unchanged ([Command](../independent-review/SKILL.md#assignment)). With none, a resumed loop keeps its recorded system and command; otherwise the reviewer is the system opposite to the loop owner's, identified as independent-review's [Session system](../independent-review/SKILL.md#session-system) does.
- **Place:** `--reviewer-run background|window` or equivalent words, passed to independent-review as its place; default `background`. A resumed loop keeps its recorded place unless `--reviewer-run` is given now, which replaces it, announced and recorded in the loop record. Refused before anything starts: `--reviewer-run subagent`, naming `background` and `window`, since a native subagent has no native review command; `--reviewer-run inline`, since reviewing one's own work is not independent. A resumed loop whose record holds the place `subagent` asks for `background` or `window` before its next review (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)).
- **Reviewer settings:** `--reviewer-model` and `--reviewer-effort` set the reviewer, passed as independent-review's `--model` and `--effort`. Effort `low` for a Claude reviewer is refused before anything starts, naming `medium`: it is the `/code-review` level, and at `low` the command reads the diff only. Under `--dual`, `--reviewer-effort` sets both reviewers' effort and a `--reviewer-model` asks which reviewer it is for (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)); prose may set one reviewer's value, passed as `--codex-model`, `--codex-effort`, `--claude-model` or `--claude-effort`.
- **Loop owner settings:** `--model` and `--effort` set the loop owner. With `--run inline`, the default, the loop owner is this session, so they are refused before anything starts: "the loop owner is this session; use --reviewer-model/--reviewer-effort for the reviewer". In another place they are the loop owner's launch settings, consumed by the launcher ([Run elsewhere](#run-elsewhere)).
- **Removed keys:** `--subagent` and `--reviewer-run subagent` (now `--reviewer-run background` or `--reviewer-run window`) and `--reviewer codex|claude` (now `--codex` or `--claude`) are refused before anything starts, naming their replacements.
- **Resume across the engine change:** a loop record written before the native review tools continues with the native engine from its pending round. An answer obtained with the old review prompt for a pending round is not applied: the round is requested again and the discarded answer spends nothing. Verdicts recorded for completed rounds stay as recorded.

The `dual` assignment has Codex and Claude review round 1, the final pass and every disposition round through [the dual review](../independent-review/references/dual.md). A scoped round of a dual loop is a single-system round by the system opposite to the loop owner's (identified as the default reviewer above is), with that reviewer's recorded command, model and effort and the recorded place, obtained from independent-review without `--dual`. Read the dual review too, and resolve both reviewers' settings by its [step 1](../independent-review/references/dual.md#1-settings-and-target).

Keep one [loop record](references/loop-record.md) outside the checkout; reuse an existing task log. Record the resolved assignment there. Use the explicit round limit, otherwise ten completed rounds. Each round's verdict, findings and fixes go to the loop record and reach the user once, in the final report, by child-sessions' [quiet wait](../child-sessions/SKILL.md#wait).

### Reviewer settings by target

Every review (round 1, scoped rounds, the final pass, disposition rounds) uses the resolved initial reviewer settings, in a single-system and a dual loop alike; a dual loop's scoped round uses its one reviewer's recorded settings. The one exception is the user's explicit settings for the final pass: they apply to the final pass and its retries only (per reviewer in a dual loop, as given), and the scoped and disposition rounds after it return to the initial settings. A request for one setting on every round is an ordinary explicit reviewer setting. Loop-owner settings are unaffected. The loop resolves and validates no other pair for the final pass, and no step waits for one.

Pass the effective settings explicitly to independent-review on every round. Announce and record each switch to explicit final-pass settings with its selection/runtime evidence. Retries retain the pending round's settings and budget; a resumed loop keeps the pending round's settings. Do not replace an already-running attempt on resume.

A loop record written before this rule may carry a `Flagship pair:` line. On resume it is history: a final pass not yet started uses the initial settings (or the user's explicit final-pass settings); a final-pass attempt already running, or the retry of one, keeps its recorded settings by the retry rule above.

## 2. Commit the reviewed state

Invoking review-fix-loop explicitly requests a task-state commit and one fix commit per round on the task branch, satisfying "commit only when asked" rules. A request that forbids commits, such as "no commits", withdraws that request: do not start this step; stop and ask the user whether to allow the task-state and fix commits or to end without review. Before the first commit, stop on detached HEAD or the default branch (`main`/`master` or configured default) and ask for branch/commit confirmation unless already authorized in the request. Under `--auto` both questions are routed by [auto.md](../child-sessions/references/auto.md#deciding), a commit consent like any other. This authority covers exactly those commits on the task branch; anything else (push, merge, rebase, amend, squash, deploy, worktree creation, installation, persistent configuration changes) needs its own authorization.

Record the pre-loop HEAD for the user's squash command. Commit task-owned staged/unstaged and untracked changes as `review-fix-loop: task state before review` if present. Select exact task paths and commit only them; an ordinary commit of the whole index could absorb unrelated staged work. Preserve unrelated index/worktree changes and record their exclusions and existing status. Before an authorized task-state or fix commit, require passing affected checks through applicable evidence or necessary execution, and satisfy explicit pre-commit gates; after each fix batch make exactly one commit naming the round and finding IDs. Apply the canonical [suite contract](../independent-review/references/checkout-state.md#resolve-checks-and-bind-suite-evidence) and [handoff recipe](../independent-review/references/checkout-state.md#run-and-hand-off-a-suite): retain original tested states and publish a separate acceptance for the new committed target. A task-state commit can retain passing dirty-state evidence when inspection proves those inputs were committed. A new SHA alone requires no suite run. Entry/round 1 and final-pass launch require accepted complete coverage or execution of the missing full checks, the pending [merge-candidate checks](#1-establish-scope-and-reviewer) aside. A fix commit that a scoped round or no review follows ([After the fix commit](#5-fix-repeat-and-finish)) may have passing affected checks with broader verification explicitly pending until completion; a fix commit the final pass follows meets the final-pass launch gate first; all named phase/producer gates remain binding. Failed required checks block dependent work without authorizing amend, squash or unreviewed corrective commits; resolve within fix authority and remaining budget or report blocked. Every review targets a recorded stable commit.

For the dual assignment, the dual review's [Complete suite](../independent-review/references/dual.md#2-complete-suite) owns serialized suite execution, writes and applicability refresh under that same contract. Reviewers receive the accepted results as data in their context files and inspect no records; fresh execution is required only for missing applicability or a resolved phase/producer obligation.

## 3. Request independent review

Obtain each attempt from independent-review, under `--auto` with `--auto` too. Pass it the review kind, the target form and target, and the data for its [context file](../independent-review/references/review-wrapper.md#the-context-file): the requirements, the full finding ledger with evidence and disposition basis, the carried candidates, and the check commands with their results. Each round gets a fresh round directory beside the loop record, which holds the round's attempt directories. Give its name a random part (`mktemp -d "<record dir>/round-<n>-XXXXXX"` on POSIX, a random directory name on PowerShell): the round directory separates attempt artifacts; independent-review separately allocates and persists its random `window-run-token`, reused on resume with phase/attempt suffixes, to name reviewer windows. Select the target and the added [wrapper line](../independent-review/references/review-wrapper.md#added-lines):

| Review | Target | Added wrapper line |
| --- | --- | --- |
| Round 1 | complete task: `<base>..HEAD`, or the files | security |
| Scoped round | `<fix commit>^..<fix commit>` | none |
| Final pass | complete task, as round 1; accumulated outside-round candidates in the context file's `Candidates` | security |
| Disposition round | complete task, as round 1, on the same HEAD | decisions only |

Scoped rounds run only after the final pass, by step 5's **After the fix commit**.

The reviewer no longer validates or executes verification: step 2 has the loop owner hold accepted complete coverage, the merge-candidate checks pending, before round 1 and the final pass, and pass the results as data. A resolved requirement that names the reviewer as the one who runs a check adds the wrapper's reviewer-run line ([What the session owns](../independent-review/SKILL.md#review-wrapper)); that check does not hold back the launch, stays `pending` until the attempt's runtime records show it ran, and keeps Verification incomplete and the loop from closing until then. Each finding's class (in scope, outside-round or outside-task candidate) comes from the attempt's `findings.md`.

In scoped rounds, the findings that `findings.md` classes as outside-round candidates (an incomplete fix stays in scope wherever its remaining failure lies): without widening this review, adjudicate them at once by evidence; accepted task defects and minor task findings go through a fix commit and step 5's **After the fix commit** within the remaining limit, other candidates get a recorded disposition. A loop record resumed with completed scoped rounds, or a scoped attempt still running, and the final pass still pending keeps the candidates those rounds recorded or that attempt returns, without fixing them, and passes them to the final pass in the context file's `Candidates`. Pre-existing outside-task problems stay separate and never block.

In a dual assignment a scoped round follows the single-system text of steps 3 and 4: one attempt directory in the round directory, the per-round budget of an initial attempt plus one retry, `checkout changed` adjudicated by the loop owner, candidates adjudicated at once by evidence. Its derived verdict is the round's verdict wherever steps 4 and 5 read one; the report keeps both reviewers' derived verdicts of the last dual review beside it. Each other review in the table, final pass and disposition rounds included, is one dual review, its resumes included, and that review is one round whatever reviewer and cross-check calls it makes. Pass the dual review (`independent-review --dual`) its recorded place, both recorded settings, the round's review kind, target form and target, the full finding ledger with its `Next D` from the [loop record](references/loop-record.md) as the ledger input of its [step 4](../independent-review/references/dual.md#4-matching), the step 2 run/acceptance records and pending coverage, and the round directory as `<dual dir>`.

## 4. Validate and decide

Each attempt comes back validated by independent-review (its **Validate** section) as `valid`, `invalid: <reason>`, `checkout changed` or shutdown-unconfirmed `blocked`, with its `result.md`, and a valid one with its `findings.md` and derived verdict; copy those facts into the round's "Result validity/completion" field. When independent-review launches nothing for an empty target, report `blocked: empty review target`. An `invalid: native review tool unavailable` attempt is not retried: report `blocked: <reason>`. A result not obtained from independent-review on a recorded commit, such as a review taken on uncommitted changes, is an invalid attempt of the pending round and never a completed round.

A shutdown-unconfirmed `blocked` return leaves the round pending: preserve its ownership records, before evidence and spent budget; do not start another reviewer, suite or fix while its stopped-process barrier is unresolved. Report the blocked reason and resume only through the same recovery gates.

Apply independent-review’s [Phase recovery and resume](../independent-review/references/checkout-state.md#phase-recovery-and-resume) to suite evidence, single attempts and retries. Failed pre-capture launches nothing/spends no attempt; unavailable post-capture spends the existing budget and retains its pre-phase baseline for recovery comparison. Unavailability alone is not a write. Capture errors persist alongside any proven difference.

Any `checkout changed` result (a moved HEAD, a new or changed file, or an index change) requires adjudication. With the unexpected work and its diff preserved and its source identified by independent-review, pause retries for implementing-session adjudication/reconciliation and affected checks within authority. Unresolved ownership/scope blocks. Do not silently incorporate a reviewer's edit in the fix commit or reset unrelated work. Outcomes:

- A reviewer write to task state, or a moved HEAD, invalidates the attempt.
- A demonstrably unrelated scratch write with required state and coverage intact is recorded without spending a retry.
- Any other invalid attempt spends the shared budget: initial attempt plus one retry per pending round, same assignment; reconciliation or new commits do not reset it. A second invalid attempt blocks.

In a dual assignment, for a round that is a dual review, the round's result is the dual review's return instead: it validates and retries each reviewer's attempts under its [Budget](../independent-review/references/dual.md#budget), which replaces the loop's per-round budget, and the loop adds no retry of its own. Record the return and its `state.md` facts in the round.

- `<dual dir>/report.md` completes the round. Its derived verdict is the round's verdict wherever steps 4 and 5 read one, the `clean` and `clean except disputed` conditions included, whatever either reviewer's derived verdict; record and report both reviewers' derived verdicts beside it, never relabelled. Adjudicate the report's confirmed findings below (an `unrated` one on its evidence, as accepted or rejected, never deferred) and take its cross-check results as given. Its `Candidates` (outside-round, outside-task, a verifier's noticed-not-verified item) follow step 3 and **Outside-scope** with one difference: no candidate of a dual review's report is fixed on this session's own evidence. A candidate of round 1's report is carried in the ledger input of the final pass's dual review as prior-finding context, where the reviewers may raise it as a finding that goes through matching and cross-check. A candidate of the final pass's report, or of a disposition round's, is carried as prior-finding context in the context file of the first scoped round if one follows, and is otherwise recorded for the user, not fixed. For these report candidates this replaces step 3's immediate adjudication; the candidates a scoped round raises follow step 3.
- `checkout changed: <state.md>`: the caller adjudicates and reconciles under the rules above. An unattributable parallel reviewer write is a reviewer write, not unresolved ownership: choose `invalidating` unless demonstrably unrelated scratch. Resume with `independent-review --dual --resume <state.md> --write scratch|invalidating` per the dual review's [State and resume](../independent-review/references/dual.md#state-and-resume), which owns content restoration, new-commit targets/baselines and spent-attempt continuity.
- `blocked: <codex|claude|codex and claude> invalid result` blocks the round.

Record every finding under a ledger ID: in a single-system loop `R<round>-F<n>` from its round and source ID, or the ID of the ledger finding it repeats ([source and ledger IDs](../independent-review/references/review-wrapper.md#findings-and-derived-verdict)); the dual review assigns `D<n>`. In a dual loop's scoped round the loop owner numbers each new in-scope finding `D<n>` from `Next D` and advances it, recording `raised by <system> <source ID>`; a finding that repeats a ledger entry keeps its ID. These findings get no cross-check and are adjudicated by the list below as in a single-system loop; one that repeats an entry rejected by cross-check without new evidence stays `repeat, unchanged`, and with new evidence the loop owner evaluates it on that evidence. When such repeats are the only findings that make the scoped round's derived verdict `CHANGES`, that verdict holds back neither clean mode: the report keeps `CHANGES`, never relabelled, and names the repeats as closed by cross-check. A dual loop record resumed with a scoped dual review already started (its `state.md` exists) finishes it as a dual review; a pending scoped round not yet started is decided again by step 5's **After the fix commit**, and a scoped round it keeps is a single-system round. Adjudicate every finding in the [record](references/loop-record.md), by its normalized severity ([severity map](../independent-review/references/review-wrapper.md#findings-and-derived-verdict)); an `unrated` finding is adjudicated on its evidence as accepted or rejected, never deferred:

- **Accepted:** a critical/important defect or spec-compliance gap requires a fix. A runnable reproduction that demonstrates a violated requirement is accepted after verification, regardless of opinion.
- **Rejected:** give a checkable quoted requirement or test demonstrating correct behavior. An unsupported opinion cannot reject a finding.
- **Minor:** an in-scope minor/style finding is fixed in the round's fix commit like an accepted one, and a round whose findings are all minor still makes that commit; step 5's **After the fix commit** says what follows it. A minor finding whose fix would change the spec or the plan, or needs a decision the requirements leave open, lies outside the task: record it **Outside-scope**, its reason naming it minor and the spec, plan or decision its fix depends on. One still unfixed at the round limit is recorded `deferred: round limit` and holds back neither clean mode.
- **Disputed:** after a recorded rejection with basis, a reviewer re-raises the same scenario/violated requirement without new evidence. The loop owner reads new evidence from the report as [review-wrapper.md](../independent-review/references/review-wrapper.md#findings-and-derived-verdict) says: a reproduction, a code reference or a requirement quote the ledger entry does not hold. A moved line alone preserves identity; new evidence instead requires fresh evaluation. Record both positions and the fix-or-dismiss question for the user, continue other work and spend no further rounds on that finding. Under `--auto` the question leaves with the report and is settled by auto.md's [`CLEAN EXCEPT DISPUTED`](../child-sessions/references/auto.md#deciding) rule, which belongs to the first session: the loop owner applies it only when it is the first session itself.
- **Outside-scope:** record pre-existing/outside-task candidates once for the final report; outside-round candidates follow step 3.
- **Not re-raised:** an accepted finding fixed in the reviewed range and absent from the next report is recorded `not re-raised`, never as verified by the reviewer.
- **Rejected by cross-check:** in a dual assignment, each finding in the report's `Rejected by cross-check` section, a `repeat` included, is recorded `rejected by cross-check: <verifier evidence>` with its raiser and source ID, and is closed: not fixed, not `disputed`, never blocking `clean`. A later report decides its next state: a repeat changes nothing, a renewed rejection records the re-raise's evidence beside the new verifier evidence, and a confirmation brings it under the rules above.

## 5. Fix, repeat and finish

Fix the round's accepted defects and minor findings in one round commit and run affected required checks. A failed required check (even PASS text with nonzero exit) blocks dependent work; use matching debugging skills, resolve within authority and rerun. Missing dependencies needing broader authority are reported blockers.

**After the fix commit:** the loop's state decides what follows the round's fix commit.

| State | Next |
| --- | --- |
| The final pass has not run | The final pass on the complete task |
| The final pass has run, and the commit fixes at least one accepted defect or the loop owner rejected a finding of the round | A scoped round on `<fix commit>^..<fix commit>` |
| The final pass has run, every fix in the commit is of a minor finding, the loop owner rejected no finding of the round, and no reviewer-run check is pending | No review: go to completion (`no review: minor-only`) |

The first row's launch meets the final pass's existing gate of step 2: accepted complete coverage or execution of the missing full checks on the fix commit. A commit that mixes an accepted defect's fix with minor fixes takes the second row. The second row's rejection clause exists so that a rejection made beside minor fixes meets a review in which the reviewer can re-raise it; a finding closed as rejected by cross-check is no rejection of the loop owner and does not count. A minor-only commit while a check a requirement gives to the reviewer ([step 3](#3-request-independent-review)) is pending, because no review has run it yet or because the commit changes one of its inputs, takes the second row, whose scoped round carries the reviewer-run line. A loop record resumed with a scoped round pending and not yet started takes its next review from this rule again.

A valid round-1 derived `CLEAN` with no minor finding to fix can finish immediately if complete required verification is applicable to that committed target under the canonical contract, including every phase/producer obligation other than the pending merge-candidate checks. Any other required failed/unrun check prevents either clean mode even when findings are CLEAN. A round with no fix commit (all findings rejected or outside-scope) runs the **one final complete pass** if it has not run. Final-pass findings return through ordinary fix-commit/scoped rounds by the rule above; refresh affected evidence and satisfy complete applicable verification after those fixes before completion. There is never a second complete code-review pass or budget reset for suite renewal. If no fix commit exists after the final pass, use at most one disposition round per disposition set on the same HEAD: a derived `CLEAN` confirms, an evidence-free repeat becomes disputed.

**No progress:** if successive rounds return the same finding set with no accepted fix, stop repeating that unchanged review. Fix confirmed defects now and verify within remaining rounds, or mark eligible evidence-free repeats disputed; an unresolved non-disputed defect blocks rather than silently disappearing.

**Checkpoint:** with a round limit above five, a loop still unfinished after five completed valid rounds pauses once, before its next fix or review, and asks the user how to go on. Give each round's target and verdict in one line, the open findings, and the cause the record shows for the extra rounds: fixes that failed their scoped review or introduced defects, findings rejected round after round, new real defects closed in each round, or rounds that closed minor findings alone. Offer:

- continue unchanged to the round limit;
- continue with reviewer settings the user names;
- stop with `blocked: stopped at the round-five checkpoint`, unresolved findings and the next action. The loop record stays, so the user can resume the loop with a stronger loop owner (`--run` with `--model`/`--effort`).

Recommend continuing when each round closed real defects and the open set is shrinking; recommend stopping when fixes keep failing or the same kind of finding keeps being rejected, since more review rounds repair neither. Record the cause, the recommendation and the answer; a resumed loop keeps the answer. Under `--auto` the question is routed by [auto.md](../child-sessions/references/auto.md#deciding).

**Limit:** every valid result counts, including final/disposition passes; invalid attempts never do. At the cap, adjudicate every open finding with a recorded reason. A last fix commit is allowed only when the review **After the fix commit** requires for it still fits within the limit; a commit that requires none is allowed. Otherwise, with an unresolved accepted defect, report `blocked: round limit` with unresolved findings and next action.

Report:

- `clean`: a valid derived `CLEAN` on final HEAD, or final HEAD is a fix commit that **After the fix commit** leaves without review, made directly on the commit of the last valid review, with every finding of that review fixed, outside-scope, a recorded minor deferral, or closed as rejected by cross-check (a `repeat, unchanged` included), and that commit's affected checks passed; required final pass completed when more than one round ran, complete applicable final verification with run/acceptance provenance and all phase/producer obligations satisfied, no unresolved accepted critical/important defects or compliance gaps, no open minor finding, and outside-round candidates adjudicated. Merge-candidate checks are the one obligation left open: the report lists each as `pending: merge candidate` with its command. When final HEAD is a fix commit left without review, the report and the loop record keep the last derived verdict as that review derived it, never relabelled, and name that commit and the minor finding IDs it closed without review.
- `clean except disputed`: the same coverage, final-pass, commit and check conditions, plus disputed findings with both positions and the fix-or-dismiss question; when final HEAD is a fix commit left without review, a `disputed` finding of the last review also counts as closed in the condition on that review's findings. A final/scoped/disposition derived `CHANGES` may close in this status when its only remaining blocking claims are evidence-free repeats now adjudicated `disputed`, every other finding is resolved/deferred/outside-scope, and no further required review remains. Preserve the derived `CHANGES` verdict and explain this disposition-based closure; never relabel the derived verdict CLEAN. Deferred minors alone do not qualify for this exception.
- `blocked: <reason>`: exhausted invalid attempts or round limit, failed required checks, missing dependencies, unresolved edit ownership, or unmet completion requirements.

Later task edits invalidate the reviewed result. Report rounds/targets/commits, assignment/evidence, checks, all decisions, deferred/disputed findings and outside-scope candidates, and under `--auto` the `## Decisions` of [auto.md](../child-sessions/references/auto.md#decisions). In a dual assignment also report the findings rejected by cross-check in their own section, each with both positions. Print the user's squash command without executing it; leave round history unsquashed. With no excluded staged work: `git reset --soft <pre-loop HEAD> && git commit`. If unrelated staged changes remain, print `git reset --soft <pre-loop HEAD> && git --literal-pathspecs commit --only -- <exact task paths>` instead, binding and quoting the task paths so the commit preserves excluded staging. `--literal-pathspecs` keeps Git from reading a file name such as `:(glob)…` as pathspec magic.
