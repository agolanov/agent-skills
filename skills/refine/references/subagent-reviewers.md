# Native Subagent Reviewer

Use the implementing system's built-in subagent tool, not a separate `codex` or `claude` CLI process. Only the reviewer is delegated; the parent keeps the refinement loop, finding decisions, and fixes.

1. Inspect the actual native tool schema and available agent settings. Resolve model and effort through [reviewer settings](reviewer-settings.md). Require controls or an existing agent definition that can select and verify the pair while preserving normal capabilities. Do not choose an artificially restricted agent type/definition merely to obtain model/effort; if only such a definition can supply the pair, report a capability blocker. Do not infer settings from the parent model or a CLI catalog.
2. Start a fresh independent reviewer with a self-contained round prompt from `refine`. Use a clean context where supported. Supply the absolute task checkout and require inspection there; native helpers may inherit the primary checkout instead. Do not request a new worktree or a writing implementer. Preserve the host's normal tool, skill, plugin and MCP access, including skill discovery and automatic invocation, rather than selecting a reduced tool set to enforce the review role. Pass the common protocol's capability and reviewed-state contract; editing tools may be used for authorized scratch artifacts outside reviewed files. Inherent runtime restrictions still apply and must be disclosed when they limit coverage.
3. Set both model and effort explicitly using the current tool's supported controls. In Codex this can be `model` plus `reasoning_effort` with `fork_turns: "none"`; actual tool/schema limits apply. In Claude use supported per-invocation controls or an existing definition. A family alias or forced runtime setting may resolve to a different model: verify the actual model and effort from runtime metadata.
4. Wait for the native agent's completed review, using the host's wait/result tools. A spawn ID, acknowledgement, or intermediate question is not a review result. Save the final answer and completion evidence outside the checkout and return them to the common protocol. Native completion has no shell exit code.

If spawning is unavailable, the exact requested pair cannot be selected/verified, or an inherited setting overrides it, report the capability blocker. Preserve the requested method and settings: do not silently switch to CLI, downgrade, or edit persistent agent/configuration files. The user can explicitly choose another assignment.

Sources: [Codex subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents), [Claude subagent models and effort](https://code.claude.com/docs/en/sub-agents).
