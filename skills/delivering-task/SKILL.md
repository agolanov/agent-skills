name: delivering-task
description: Takes one or more task documents (a plan, a spec with one plan, a task brief, or a directory of them) through implementation and cross review to a merge into the main branch and cleanup, recording follow-ups, several documents as a dependency-ordered queue. Use when tasks are ready to implement and should be executed, reviewed and merged, or, with `--no-merge`, left as reviewed branches.

# Delivering Task

For each clean/path gate and continuation below and in child briefs, use the four ordinary Git commands and identity checks in [checkout state](../independent-review/references/checkout-state.md#direct-use-preflight), with process-local `GIT_OPTIONAL_LOCKS=0`, actual exits and raw output files. A clean gate requires successful commands and empty status and diffs; path gates parse NUL-delimited status and compare exact repository-relative paths, including both rename paths. Failed or unavailable Git evidence stops the dependent action. Use ordinary Git for other read-only checks, retaining real exits. Evidence has the reference's ignored/untracked-content, Git flags/normalization, nested-repository and transient-write limits. Stage/commit only owned paths; write, merge and push authority stays explicit.


`delivering-task <document | directory>... [--no-merge] [--parallel N] [--independent] [--run window|inline|subagent|background] [--agent claude|codex] [--impl solo|subagents|direct] [--model M|cli-default] [--effort E|cli-default] [--reviewer-run background|window] [--reviewer-model M|cli-default] [--reviewer-effort E|cli-default] [--reviewer-agent claude|codex] [--reviewer-dual] [--spec S] [--branch B] [--resume] [--auto]`

One document: Execute (the sections Preflight through End below), then Merge and Cleanup. A refusal, a stop or a `failed` status in Execute ends the run with nothing merged. With `--no-merge` the run stops after End with a ready branch and reports it. Several documents or a directory: read [queue.md](references/queue.md) and follow it; its per-unit work is the sections below. The queue text is read only in this case. `--spec`, `--branch` and `--resume` take one document only: given with several documents or a directory, they stop the run before anything starts, naming the key; the queue finds leftovers itself. `--parallel` and `--independent` apply to several documents: `--independent` (the queue infers no dependency; a `**Depends on:**` line still counts) given with one document stops the run before anything starts, naming the key.

The child owns implementation, refinement and, in the tracked layout, its follow-ups commit. `--run` places it ([Launch](#launch)): by default in a visible `window`, else in a `subagent` or a `background` CLI, or, under `--run inline`, in this session. The root checks Git/status facts, records follow-ups the child cannot commit and integrates; it does not write product code, add commits to the task branch, or repeat the child's tests or review, except under `--run inline`, where it is that child. Follow-ups are written only through [follow-ups.md](references/follow-ups.md), by the child in the tracked layout or by End 3; in the tracked layout Merge carries them to main with the branch.

Under `--auto` read child-sessions' [auto.md](../child-sessions/references/auto.md) before anything starts: every question below that would go to the user is routed by its Deciding, the implementer brief says `Auto: yes`, and the report lists `## Decisions`.

## Phases

A session performs Prepare, Wait and Accept in order as one root. A session whose brief or prompt carries `Phase: prepare` or `Phase: accept` performs that phase alone and ends as that brief says, naming the record's path. Without a `Phase:` line, continue from Launch to Wait and Events yourself; do not end after Prepare. `--run inline` follows Inline instead, with no phases or record, except for the phase-alone inline place under a caller below. With several documents, a single queue root performs every unit's phases itself by queue.md; a phase-alone session follows [queue Phase agents](references/queue.md#phase-agents). Each unit has its own record.

| Phase | Who performs it | Sections to read and perform | References to read |
|---|---|---|---|
| Prepare | The single root, or the Prepare agent | Preflight, Implementation mode, Worktree, Brief, Launch | The Prepare list below |
| Wait | The single root, queue root for its units, or the phase agents' caller (for a queue too) | Wait | child-sessions SKILL.md Wait and Dialogs; launch-settings Child settings check and Places for a subagent first status |
| Accept | The single root, or the Accept agent | Events, Verify, End, Merge, Cleanup | The Accept list below |

Read each phase's references when reaching that phase. Prepare alone launches a `window` worker (open, Startup, early settings check); for `subagent` or `background` it starts nothing, writes `Action: start` and ends. Accept alone ends after a return to the worker or a reopen, writing Waiting (a non-window return as `Action: continue`) instead of waiting. Prepare alone starts no non-window worker, so it does not apply Preflight's refusal for this session being itself a subagent: judge that combination for the caller, which is never a subagent because both orchestrators refuse `--run subagent`; a worker start the host refuses is `launch failure`. Every other refusal stays Prepare's, including an implementer subagent that would itself start subagents.

**Inline place under a caller.** A phase-alone Prepare whose place resolves to `inline` (the key, the user's words, or a resumed brief's recorded place) first applies inline's own refusals as written, then performs the run as place `subagent` with both settings fields `cli-default`. This takes precedence over Inline's no-phase path for this call. The worker brief says `Place: subagent` and `Launch settings: model cli-default (cli-default), effort cli-default (cli-default); resolved <date> from the inline place under a caller`; Waiting has `Action: start subagent` and `Action settings: model cli-default, effort cli-default`. Put `inline place under a caller: subagent worker with the host's default settings, not verified` in Report carries; End 4's and Cleanup 2's implementer settings line uses it in place of `inline: current session`. A queue does this for every unit, one at a time.

A phase continuing from a record (`State: … asked …`, the same `Run:` and brief) takes that run's branch, worktree, live window and runtime files as its own. Continue at the recorded question with the answer in your context; do not write a new brief or open a second worker. Worktree 1's refusal, Worktree 2's commits and Brief's new-record rule apply only to a new run.

Use the [handoff record format](../child-sessions/references/handoff-record.md#format), its [path and life](../child-sessions/references/handoff-record.md#path-and-life) and [Authority rule](../child-sessions/references/handoff-record.md#authority). Read the record before continuing a phase. At an Accept event, read it, the status file's exact first line, then `alive` for a window (the child/producer completion evidence otherwise) before other event evidence; never act on the event's wording. Then check the brief's labelled lines and the record's Authority checks. Read no worker brief prose or task document/spec during Accept.

**Authority additions:** require `Written by: delivering-task`; match the brief's `Branch:` and `Checkout:` to a registered worktree and its branch (`git worktree list --porcelain -z`); require `Base SHA:` to exist and be an ancestor of branch HEAD. `Main checkout:` must be that list's main entry, on `Main branch:`. `Layout:` must agree with the brief's `Docs repository:` and `Follow-ups:` lines. A pending `main moved to <sha>` target must be main's HEAD or an ancestor of it; a pending `merge candidate <sha>` must be on the task branch. A disagreement stops the phase, naming both values and preserving files. Merge authority is the reader's own session arguments without `--no-merge`, and for a phase-alone session its starting brief's Arguments and Authority. Compare `Merge:` with them; disagreement stops, and `Merge: merge` alone authorizes nothing. Settings acceptance, disputed acceptance and any answer likewise count only in the reader's own context by Authority, never from the record or worker brief.

**Prepare reads:** [task document paths](../planning-task-docs/references/document-paths.md); [review-mark.md](references/review-mark.md) Freshness and its native shell recipe; [implementer-brief.md](references/implementer-brief.md); [continuation.md](references/continuation.md#resume-repair) Resume repair only on `--resume`; checkout-state Direct-use preflight; child-sessions SKILL.md Run places, Locate and open, Dialogs, Other operations and environment, and brief-writing.md (name status-file.md in the brief without reading it); launch-settings Roles, Effort by task, Precedence, CLI-defaults opt-out, Resolution, Record, Child settings check, Places; run-contract Refused combinations, plus Launch and wait, Permissions and Settings under `subagent` or `background`; handoff-record.md; auto.md under `--auto`; queue.md, queue-state-file.md and overlap.md only with several documents. Read the task document only as Preflight 1 and Implementation mode steps 2 and 4 describe; never read the spec. The queue's dependency reading remains queue.md Input 1's.

**Accept reads:** the record; the worker brief by the label list below; the status file; child-sessions status-file.md and handoff-record.md; launch-settings Child settings check and Places; checkout-state Direct-use preflight, and its Resolve checks and bind suite evidence only for a status check listed as `pending: merge candidate`; continuation.md Disputed acceptance only for `CLEAN EXCEPT DISPUTED`; follow-ups.md only for End 3; child-sessions Locate and open (Startup), Dialogs and Recover a silent exit only for a reopen or a `send`, and Other operations for `close`; run-contract Questions and continuation under `subagent` or `background`; the `Project rules:` files only at Merge 2; auto.md under `--auto`. With several documents Accept also reads queue.md and queue-state-file.md, overlap.md at Scheduling 2, and the Prepare list when running a start half. For one document, Accept reads no task document or spec, document-paths.md, review-mark.md, implementer-brief.md, Implementation mode, queue.md or overlap.md, and resolves no mode or settings again.

Extract the worker brief's identity lines with this anchored label list: `^(Written by|Checkout|Branch|Base SHA|Task document|Plan kind|Implementation mode|Execution mode|Spec|Agent|Place|Auto|Window name|Launch settings|Reviewer settings|Reviewer run|Reviewer agent|Git checks|Suite evidence|Docs repository|Ignored test material|Follow-ups|Status file|Opened): `. Keep each matching line's value as written. Besides them read only the root-owned `## Disputed acceptance` section when it exists.

**Facts for this skill:**

```text
Invocation: <UTC ISO 8601 to the second when this record was created> <new|resume>
Main checkout: <absolute path>
Main branch: <name>
```

The record's `Run:` is the brief's `Branch:` exactly, `Checkout:` the task worktree. Keep root Git boundary outputs in a fresh directory outside Git: `Root evidence:` names that directory, where Accept adds its own outputs. Branch, base, documents, mode, place and settings remain on the brief's labelled lines. `Reopen:` holds the one reopen shared by silent exit and dead-before-send, or the run contract's one non-window restart. Returns are not limited to one: `Return to worker:` holds the latest archived status path and `Pending return:` its reason. Keep Report carries (announced non-window place, Worktree 2's nonzero count lines, open fallback, missing send, dialog counts or `dialogs not observable`, reopen and reason), Decisions and Told the user current as facts change.

## Preflight

1. Resolve the main checkout, main branch, the absolute task document path, and applicable project rules. Require the main checkout on its main branch; uncommitted changes are allowed and stay untouched. The check still takes a four-command boundary, and failed Git evidence stops. Recognise the document without reading it through: use its name and place, the header searches task document paths names, and its last line and the freshness recipe for its review mark:
   Read [task document paths](../planning-task-docs/references/document-paths.md) for location/kind, plan/spec pairs and discovered candidates, then apply:
   - **Plan**: find its spec by that reference, with `--spec` first; without a match use `None`, with no question.
   - **Spec**: find its plans by that reference. None: refuse before any worktree or window, telling the user to write the plan with `planning-task-docs`. One: that plan is the task document, this spec its spec. Several: list them and ask the user which one to execute (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)).
   - **Other**: any other file is a task document implemented directly (a brief, a task text). Spec `None`.

   `--spec` is accepted only with a plan. Layout: the docs repository is `git -C <document-dir> rev-parse --show-toplevel`, named by its main-checkout absolute path. **Tracked**: it is the project and `git -C <main-checkout> check-ignore -q <document-dir>` exits non-zero. **Separate docs**: it is another repository (nested in an ignored directory or elsewhere); require its main checkout on its main branch the same way, uncommitted changes allowed and untouched. **Ignored**: it is the project and that `check-ignore` exits 0 (ignored without its own repository). Show the user the document's kind, its spec and the layout, and the review-mark state of the task document and its spec per [review-mark.md](references/review-mark.md): fresh with verdict, reviewer and date; else `none` or `stale` with the failing freshness condition. The mark state is information only; continue whatever it is.
2. Decide the implementation mode per [Implementation mode](#implementation-mode). `--impl` is an explicit mode; a value invalid for the document kind (`subagents` for another document, `direct` for a plan) stops before any worktree or window, naming the value and the kind. A caller that decided the mode by that section's rule (as the queue does for its units) passes it labelled as caller-decided: record it with source `rule` without deciding again; it is not an explicit override. A mode the user gave the caller explicitly is passed as an explicit `--impl`. Show the mode, its source, its reason and, for the `solo` mode, the model and effort with their reason (under `--run inline`, `effort: none, --run inline` instead) beside Preflight 1's display, as information; the run continues without a question. Select `--agent`, otherwise identify the root's own system from session identity as independent-review's [Session system](../independent-review/SKILL.md#session-system) does; unknown identity requires clarification (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)). For `--resume`, recover recorded launch identity, its `Implementation mode:` and `Place:` lines included, subject to the provenance checks below; conflicting explicit overrides stop. The place is the recorded one on `--resume`, else `--run`: `window` when absent, else `inline`, `subagent` or `background`; the user's words choosing a place count as the key, and any other value stops before any worktree or window. Announce a place other than `window`. Refuse before anything starts, naming the combination, what run contract [Refused combinations](../child-sessions/references/run-contract.md#refused-combinations) refuses for the implementer, the agent and place recovered on `--resume` included: under `--run inline`, an `--agent` naming a system other than this session's or an explicit `--model` or `--effort`; under `subagent`, an `--agent` naming a system other than this session's, this session being itself a subagent on a host whose subagents cannot start subagents, or, on a host whose subagents cannot start subagents, the `subagents` mode, since the implementer subagent would start them. In every place `--reviewer-run subagent` is refused, naming `background` and `window`: a native subagent has no native review command. Under `--run inline` resolve no settings, the solo effort included: the implementer is this session ([launch settings Places](../independent-review/references/launch-settings.md#places)). In every other place, `window` included, and except on `--resume`, resolve the implementer's settings per [launch settings](../independent-review/references/launch-settings.md#precedence) for the selected agent: `--model`/`--effort` are explicit values, `cli-default` is a per-field [opt-out](../independent-review/references/launch-settings.md#cli-defaults-opt-out), and every other field takes the default of the mode's role per [launch settings](../independent-review/references/launch-settings.md#roles): `solo implementer` for the `solo` mode, with the model and effort of the solo settings rule; `implementer` for `subagents` and `direct`. So `--model cli-default` in `solo` mode omits only the model; the effort is still the solo settings rule's `medium` or `high`, passed explicitly. A caller that resolved values from the policy (as the queue does for its units) passes them labelled as policy values: record them with source `policy` without re-resolving; they are not explicit overrides. An unresolved or unsupported pair stops before any worktree or window. Under `subagent` and `background`, resolve and pass the pair as launch settings [Places](../independent-review/references/launch-settings.md#places) says for the place; a pair the place cannot select and verify is refused before launch, naming the place and the pair. Resolve the reviewer system, the user's words choosing a reviewer counting as the keys. Refuse before any worktree or window, naming the key and its value: `--reviewer-agent` with a value other than `claude` or `codex`; `--reviewer-agent` together with `--reviewer-dual`; `--reviewer-dual` together with any `--reviewer-model`, `cli-default` included (under the dual review `review-fix-loop` asks which reviewer a `--reviewer-model` is for, and no key here says which). The reviewer system is `dual` under `--reviewer-dual`, else the `--reviewer-agent` value, else the system opposite to the child's agent; a reviewer of the same system as the child is accepted. On `--resume` it is the recorded one that Worktree 3 reads, never resolved again from the keys. It fills the brief's `Reviewer agent:` line as `<claude|codex|dual> (explicit)` when a key or the user's words set it, else `(default)`. Validate explicit `--reviewer-model`/`--reviewer-effort` values for that reviewer system (effort `low` for a Claude reviewer is unsupported, naming `medium`; under `dual` the effort is validated for both systems, so `low` is refused, naming `medium`): a model of another system or an unsupported pair stops before any worktree or window, naming the value and the reviewer system; `cli-default` is accepted. These values fill the brief's Reviewer settings line; without them it says `reviewer policy`. `--reviewer-run <place>` fills the brief's Reviewer run line as `<place> (explicit)`; without it the line says `background (default)`. A place other than `background`, `subagent` or `window` stops before any worktree or window. Never infer the agent from executable availability, environment, directory names, or model. Default branch to the task document's stem (the plan's stem for a plan or a spec resolved to its plan); validate with `git check-ref-format --branch`, asking for a valid override if invalid (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)). Use window `<name> = impl-<branch>` for `[A-Za-z0-9_-]+` branches; otherwise replace disallowed branch characters with `-` and use `impl-<slug>-<hash8>` (first eight SHA-256 hex characters of the full branch name). Record the unique name; never alias slash/dot branches by slug alone.
3. Locate root's installed `child-sessions/SKILL.md`; read its Run places, Locate and open, Dialogs and Other operations and environment sections, and its owned `references/brief-writing.md`. Name its `references/status-file.md` in the brief; the worker and Accept read that contract. Read launch-settings and run-contract only by Prepare's reference list; run-contract governs non-window launch, wait, questions and permissions. Resolve its installed platform entrypoint by absolute path (Bash `scripts/child-session`; native Windows `scripts/child-session.ps1` through the installed PowerShell vector in its platform reference). Its command/status contract governs every call below. Set `<runtime>` from successful `runtime-dir` output, outside Git.
4. Check the selected child's actual installed catalog/directories, this session's own under `--run inline`: Claude's `~/.claude/skills`, enabled `~/.claude/plugins`; Codex's `~/.codex/skills`, `~/.agents/skills`, enabled `~/.codex/plugins`; plus project `.claude/skills` and `.agents/skills` available to that child. Resolve readable absolute paths for `review-fix-loop`, `independent-review`, `child-sessions` when the Reviewer run place is `window` (the child opens that reviewer window itself), and, for a plan, the execution skill its mode names (`executing-plans` for `solo`, `subagent-driven-development` for `subagents`): a missing one stops before opening and is never replaced by the other. Another document needs no execution skill. Follow-ups writing is this skill's [follow-ups.md](references/follow-ups.md), never a separate skill: the child in the tracked layout and End 3 use this skill's installed copy. Verify checkout-local paths remain available in the worktree. Executables or the root's catalog alone do not prove child skill availability. Missing dependencies stop before opening; report them for the user to install, without substitution.

## Implementation mode

Preflight 2 decides one implementation mode per run, after Preflight 1 has identified the task document and before any settings are resolved. The mode names the child's execution skill and its [launch settings role](../independent-review/references/launch-settings.md#roles):

| Mode | Task document | Brief's Execution line | Role |
| --- | --- | --- | --- |
| `solo` | plan | `executing-plans` | solo implementer |
| `solo` | other | `None: direct implementation` | solo implementer |
| `subagents` | plan | `subagent-driven-development` | implementer |
| `direct` | other | `None: direct implementation` | implementer |

`subagents` is valid only for a plan, `direct` only for another document, `solo` for both.

1. **Given mode.** An explicit `--impl` valid for the kind, a caller-decided mode (source `rule`) and, on `--resume`, the mode the brief records (Worktree 3) are taken as given. An explicit `--impl solo` on a large document is honoured, with no warning or question. The rule in step 2 runs only when none of these applies.
2. **Rule.** Read the document and choose, by your own judgement, the mode valid for its kind that will carry it out with the fewest tokens and in the least time.
3. **Solo settings.** Whenever the final mode is `solo`, whatever its source, outside `--run inline` (which launches no child and resolves no settings), choose the least capable tier sufficient for the whole task document using the table below. Use the most demanding step, not the average step or file count; a mostly mechanical plan with an architectural decision takes the architectural row. A given mode skips step 2, never this step. Apply the choice independently to each field without an explicit value (`cli-default` included), recorded value or caller-resolved policy value. Resolve the selected family to an exact supported model and validate the pair through launch-settings before launch; pass both fields explicitly except opted-out fields. The parent's model is not a default for the child.

   | Work required from the solo child | Claude family | Codex family | Effort |
   | --- | --- | --- | --- |
   | Complete code/text supplied, requiring transcription and checks only, or an isolated mechanical edit with no design decisions | Haiku | Luna | medium |
   | Prose instructions requiring implementation choices, ordinary integration or debugging | Sonnet | Terra | high |
   | Architecture/design decisions, subtle concurrency or similarly demanding correctness reasoning | Opus | Sol | high |

   These are family choices, not pinned versions: use the latest available version of the selected family under launch-settings Resolution. Missing or unsupported settings stop before launch without silently substituting a different tier. Model and effort overrides remain independent; overriding the model does not change the row's effort. The choice governs this solo child's implementation and later fixes, not its separate reviewers or children. Resumes retain recorded settings.
4. **Implementer effort.** Whenever the final mode is `subagents` or `direct`, whatever its source, outside `--run inline`, choose the effort by launch-settings' [Effort by task](../independent-review/references/launch-settings.md#effort-by-task) from the most demanding step of the task document. A given mode skips step 2, never this step. Apply the choice only to an effort field without an explicit value (`cli-default` included), recorded value or caller-resolved policy value. The model stays the `implementer` role's latest available Opus (Claude) or latest available Sol (Codex), resolved and validated through launch-settings before launch.
5. **Output.** The mode; its source, `rule` (decided here or by the caller) or `explicit`; a one-sentence reason; for `solo`, model and effort with the most demanding step that justified the tier; for `subagents` and `direct`, the effort, with the most demanding step that justified it when this step chose it (the brief's `Launch settings:` line carries it as `effort step:`); or under `--run inline` `settings: none, --run inline`, since steps 3 and 4 compute none. The brief records the mode as `Implementation mode: <solo | subagents | direct> (<rule | explicit>); <reason, one sentence>` and the concrete pair with per-field sources on its existing `Launch settings:` line.


## Worktree

1. Use the project worktree convention, otherwise `<main-checkout>/.worktrees/<branch>`. Resolve the main checkout and selected path, including existing symlinks. For a path inside the main checkout, run `git check-ignore`; if it is not ignored, tell the user and stop without changing ignore rules. For an external path, apply the same ownership/existence checks without an ignore prerequisite. For a new run only, refuse any existing branch or worktree, naming both, unless `--resume`; a phase continuing its own record keeps them.
2. For a new task (a `--resume` commits nothing), first commit its documents, the paths this step owns: in the tracked and separate-docs layouts, the task document and then its spec when not `None`, each alone in the repository holding it, `<repo>` = `git -C <document-dir> rev-parse --show-toplevel`. For each document take a fresh four-command boundary of `<repo>`; failed Git evidence stops, as at every gate. The document has uncommitted changes (untracked, staged or unstaged alike) when its exact repository-relative path `<rel>` equals a path of the NUL-delimited status, either path of a rename or copy entry included. With changes run `git -C '<repo>' --literal-pathspecs add -- '<rel>'`, then `git -C '<repo>' --literal-pathspecs commit -m 'docs: <basename>' -- '<rel>'`, and show `committed <rel> <sha7>`; without changes commit nothing. Each path and message is one literal shell argument, quoted for the shell that runs it (inside POSIX single quotes a single quote is written `'\''`; inside PowerShell single quotes it is doubled), and `--literal-pathspecs` keeps Git from reading a file name as pathspec magic. The pathspec commits the document alone: other staged changes stay staged, unstaged and untracked paths stay as they are, and when the document is one side of a staged rename only its own path is committed, the other side staying as it is. A failing `add` or `commit` stops before any worktree or window, reporting Git's error. The ignored layout commits nothing and shows no commit line, its documents never being committed; the count lines that follow still apply. Then show `unrelated uncommitted changes left untouched: <count>` for the main checkout and, in the separate-docs layout, `<docs main checkout>: unrelated uncommitted changes left untouched: <count>` for the docs repository. The count is the number of distinct paths in the status of that repository's last boundary (this step's, else Preflight 1's), both rename or copy paths counted, other than a document committed here; the paths are never listed, and a count of 0 shows no line. The commits and counts are information; the run continues without a question. Then record full main HEAD as `<base-sha>` and run `git worktree add -b <branch> <path> <base-sha>`; in the tracked layout that base includes the document commits, so the worktree holds the documents. Verify its branch and HEAD match. Keep runtime files under the helper's `<runtime>` outside Git, creating parent directories for nested branch names.
3. For `--resume`, require the prior runtime brief whose identity block carries `Written by: delivering-task`. Any other brief stops before reopening, naming it: “brief written by a removed skill; finish that run with the catalog that started it, or remove its branch, worktree and runtime files by hand”. Require in it base, absolute task document/spec identity, branch, checkout, its `Place:` line, the window name for a `window` place, and its `Implementation mode:`, `Launch settings:`, `Reviewer settings:` and `Reviewer run:` lines. Match it to the requested task and registered Git worktree/branch; validate the recorded base exists and belongs to the task history. Reuse the recorded base/window identity, never today's main as a guessed replacement, and the recorded place, settings and `Reviewer run:` place, never re-resolved: an explicit flag equal to the recorded value is accepted, a different one stops; caller-resolved policy values never conflict, the recorded values win. A recorded `Reviewer run: subagent` cannot continue: ask for `background` or `window` before reopening (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)) and write the answer into the brief's Reviewer run line. The recorded `Reviewer agent:` line is reused the same way, never re-resolved: an explicit key naming the recorded system (`--reviewer-agent X` for a recorded `X`, `--reviewer-dual` for a recorded `dual`, whatever the recorded source) is accepted, a different one stops, naming both values. A brief written before that line existed has none: read it as `<the system opposite to its Agent:> (default)` under the same rule; the line is not among those required above and is never inserted. The recorded `Implementation mode:` line is reused the same way, never decided again: an explicit `--impl` equal to it is accepted, a different one stops; a caller-decided mode never conflicts, the recorded mode wins. A brief written before the rename records the mode as `Execution mode:` with `inline` for `solo`; read it as `Implementation mode:` with `solo`. Missing, conflicting or ambiguous provenance stops. Preserve current work for the child; after those provenance, identity and Git continuation gates and before archiving status, read and perform [Resume repair](references/continuation.md#resume-repair). Then archive any prior status to an unused suffix and append “Continue from the current state of the checkout: read git log and record the ordinary Git evidence and verify checkout/branch/HEAD first.” An old terminal report cannot complete a resumed run.

2. With main HEAD at the recorded base `<base>`, run the dirty-path gate immediately before `git merge`: take a fresh four-command boundary of the main checkout `<main>`; failed Git evidence stops, as at every gate, and a HEAD other than `<base>` means main moved: return to Merge 1. Staged changes (a non-empty cached diff, or a status entry whose first column is neither a space nor `?`) stop, naming the staged paths: Git refuses a non-fast-forward merge while the index differs from HEAD, even for unrelated paths. Otherwise list the branch's paths with `git -C <main> diff --no-renames --name-only -z <base> <branch>` and the paths it adds with the same command plus `--diff-filter=A`, both NUL-separated and never word-split. A branch path intersects when it equals a status path, either rename or copy path included; when it or one of its leading directories (`a` and `a/b` for `a/b/c`) is reported ignored and exists as anything but a directory; or when the branch adds it and it exists as a directory holding untracked content, ignored files included: `git -C <main> --literal-pathspecs ls-files -z --others -- <path>`, the path one literal argument, prints an entry (files tracked there are the branch's own deletions and pass; a nonzero exit is unavailable evidence and stops). Git overwrites or deletes such ignored content silently and refuses only for untracked content that is not ignored. For the ignored test take the branch paths and their leading directories, leave out every path below a leading directory that exists in the main working tree as anything but a directory (Git does not look beyond a symlink; that leading path is judged alone), and feed the rest, each written as `./<path>` (a name beginning with `:` would otherwise be read as pathspec magic and fail the command), NUL-separated, as standard input to `git -C <main> check-ignore -z --stdin` (exit 0: it prints the ignored ones as given, NUL-separated, and their leading `./` is dropped before comparing; 1: none is ignored; any other exit is unavailable evidence and stops). Judge existence and directories in the main working tree by lstat: a dangling symlink exists and a symlink is never a directory (on POSIX `test -e || test -L`, and `test -d` only with `! test -L`). Intersections stop, naming the main working tree paths in the way. A staged or intersecting stop is reported as `dirty main: <paths>` and keeps window, worktree, branch and status; nothing is stashed, unstaged, restored or committed. With one document the run ends there; the queue holds the unit instead. Unavailable evidence stops the same way, without the label. With no staged change and no intersection, in the main checkout run `git merge --no-ff <branch>` with Git's default message: no `-m`, no `-F`, no edited message (the queue's Input 3 finds merged units by the subject `Merge branch '<branch>'`). If it exits non-zero, run `git -C <main> rev-parse -q --verify MERGE_HEAD`. Exit 1, no merge in progress: Git refused before starting (a path changed after the gate, or untracked content that is not ignored in a directory/file collision the exact-path comparison misses); stop as `dirty main: <paths Git names>` with Git's message, keeping everything as a gate stop does, and run no `git merge --abort`: there is no merge to abort. Exit 0, a merge in progress: a conflict; run `git merge --abort`, report and preserve the child/worktree. Any other exit is unavailable evidence: stop, keeping everything. When `git merge` exits 0, capture the merge SHA, then explicitly compare `git rev-parse HEAD^{tree}` with `git rev-parse <branch>^{tree}`. Inequality stops cleanup. Run checks again only when project rules explicitly require them after merge; ordinary “after changing code” requirements are satisfied by the child's verified results. Post-merge check failures stop with evidence preserved.
