# Delivering Task

For each clean/path gate and continuation below and in child briefs, use the four ordinary Git commands and identity checks in [checkout state](../independent-review/references/checkout-state.md#direct-use-preflight), with process-local `GIT_OPTIONAL_LOCKS=0`, actual exits and raw output files. A clean gate requires successful commands and empty status and diffs; path gates parse NUL-delimited status and compare exact repository-relative paths, including both rename paths. Failed or unavailable Git evidence stops the dependent action. Use ordinary Git for other read-only checks, retaining real exits. Evidence has the reference's ignored/untracked-content, Git flags/normalization, nested-repository and transient-write limits. Stage/commit only owned paths; write, merge and push authority stays explicit.


`delivering-task <task-document> [--spec <spec>] [--agent claude|codex] [--execution inline|subagents|direct] [--model M|cli-default] [--effort E|cli-default] [--reviewer-model M|cli-default] [--reviewer-effort E|cli-default] [--branch B] [--resume]`

Two halves: Execute, then Merge and Cleanup. Standalone they run in sequence; `delivering-task-queue` decides when each half runs. The child owns implementation, refinement and, in the tracked layout, its follow-ups commit. The root checks Git/status facts and integrates; it does not write product code, add commits to the task branch, or repeat the child's tests or review. Follow-ups are written only by `executing-task-docs` End; the merge half carries them to main with the branch.

## Execute

Locate the root's installed `executing-task-docs/SKILL.md`, read it and its references completely, and perform it exactly as written with this run's task document and options, through its End. `--model/--effort` set the implementer only; `--execution` and `--reviewer-model/--reviewer-effort` go to `executing-task-docs` unchanged; this skill sets no default of its own. A refusal, a stop or a `failed` status ends the run here, with nothing merged.

## Merge

1. Immediately before merging, require main still on its branch, and compare full main HEAD to recorded base. If changed, archive status, retain the prior brief and append the new target plus this one-time authorization: “main moved to <sha>: rebase onto it, rerun the checks and one fix-review round, write a new status”. Tell the child to use `<sha>` as its reporting/review base. Send that sentence word for word, with `<sha>` filled in, to the same child through `executing-task-docs` Open and wait 5: a dead child gets that step's reopen with the authorization as the line to send, counted against the same run. Then wait, verify a fresh report against that target, then update the recorded Base SHA in the runtime brief. Perform `executing-task-docs` Verify and End again, then repeat this latest-main check; no stale status or merge before refresh.
2. With main HEAD at the recorded base `<base>`, run the dirty-path gate immediately before `git merge`: take a fresh four-command boundary of the main checkout `<main>`; failed Git evidence stops, as at every gate, and a HEAD other than `<base>` means main moved: return to Merge 1. Staged changes (a non-empty cached diff, or a status entry whose first column is neither a space nor `?`) stop, naming the staged paths: Git refuses a non-fast-forward merge while the index differs from HEAD, even for unrelated paths. Otherwise list the branch's paths with `git -C <main> diff --no-renames --name-only -z <base> <branch>` and the paths it adds with the same command plus `--diff-filter=A`, both NUL-separated and never word-split. A branch path intersects when it equals a status path, either rename or copy path included; when it or one of its leading directories (`a` and `a/b` for `a/b/c`) is reported ignored and exists as anything but a directory; or when the branch adds it and it exists as a directory. Git overwrites or deletes such ignored content silently and refuses only for untracked content that is not ignored. For the ignored test feed the branch paths and their leading directories, NUL-separated, as standard input to `git -C <main> check-ignore -z --stdin` (exit 0: it prints the ignored ones, NUL-separated; 1: none is ignored; any other exit is unavailable evidence and stops). Judge existence and directories in the main working tree by lstat: a dangling symlink exists and a symlink is never a directory (on POSIX `test -e || test -L`, and `test -d` only with `! test -L`). Intersections stop, naming the main working tree paths in the way. A staged or intersecting stop is reported as `dirty main: <paths>` and keeps window, worktree, branch and status; nothing is stashed, unstaged, restored or committed. Standalone the run ends there; `delivering-task-queue` holds the unit instead. Unavailable evidence stops the same way, without the label. With no staged change and no intersection, in the main checkout run `git merge --no-ff <branch>` with Git's default message: no `-m`, no `-F`, no edited message (`delivering-task-queue` Input 3 finds merged units by the subject `Merge branch '<branch>'`). If it exits non-zero, run `git -C <main> rev-parse -q --verify MERGE_HEAD`. Exit 1, no merge in progress: Git refused before starting (a path changed after the gate, or untracked content that is not ignored in a directory/file collision the exact-path comparison misses); stop as `dirty main: <paths Git names>` with Git's message, keeping everything as a gate stop does, and run no `git merge --abort`: there is no merge to abort. Exit 0, a merge in progress: a conflict; run `git merge --abort`, report and preserve the child/worktree. Any other exit is unavailable evidence: stop, keeping everything. When `git merge` exits 0, capture the merge SHA, then explicitly compare `git rev-parse HEAD^{tree}` with `git rev-parse <branch>^{tree}`. Inequality stops cleanup. Run checks again only when project rules explicitly require them after merge; ordinary “after changing code” requirements are satisfied by the child's verified results. Post-merge check failures stop with evidence preserved.

## Cleanup

1. After tree equality and required post-merge checks succeed, run `child-session close <name>` using the resolved executable and recorded window name, then require `child-session alive <name>` to exit 1. Then run non-forced `git worktree remove <path>` and `git branch -d <branch>`, in that order. A failure stops cleanup and is reported, never forced away. Consult the launch capabilities: proven owned process exit and terminal-window closure are separate; unsupported window closure leaves a reported retained window. A retained Windows window or shell still holding the checkout as its working directory needs direct user attention before removal.
2. Report merge SHA, child commits, the execution mode line and the implementer and reviewer settings lines from `executing-task-docs` End 4, follow-ups path and count (with its commit, or where it was written locally), required post-merge check results, and the dirty-path gate's line `unrelated uncommitted changes left untouched: <count>`, the count being the number of distinct paths in its boundary's status, both rename or copy paths counted, never listed, with no line for 0. Root writes only runtime artifacts and what `executing-task-docs` End records; one task yields one merge.
