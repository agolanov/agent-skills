## Inline

This session is the implementer: no child or window. Inline has no phases and writes no handoff record; record-reading and record-update clauses below do not apply to it.

1. Once Brief has written the brief, read the SKILL.md paths its Required installed skills lines name and perform its work yourself in the brief's Checkout: the mode's execution skill, the checks, `review-fix-loop` and, in the tracked layout, the follow-ups commit, within the brief's boundaries. Talk to the user directly in this session: ask here what the brief would put in a `blocked` status; under `--auto` route those questions by [auto.md](../../child-sessions/references/auto.md#deciding) instead. End by writing the status file as the brief says; `failed` stops as Events' failed stop says. On explicit resume, continue the same way from the continuation brief.
2. Verify, End, Merge and Cleanup apply as written, except: a return to the child per Events **Return to the child** (Verify 1–3, End 2) and Merge 1's main-moved and merge-candidate authorizations are this session's own work: archive the status as Events **Before every send** says, do what the line says within the brief's authority, write a fresh status and verify again. Verify 1's settings line does not apply; End 4's implementer settings line says `inline: current session` and names this session's system; Cleanup closes no window.
