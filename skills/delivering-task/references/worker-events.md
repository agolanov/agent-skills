# Delivery worker events

## Window controls

A window brief uses the template's fixed `Terminal controls:` line. After every open, including reopen and resume, check the checkout and launch identity from `capabilities <name>`. Use only the current launch's supported `peek`, `send` or `key`. Keep capabilities out of the worker brief and conversation.

If any of those controls is unavailable, use brief/status files. Check Told the user and give the direct-attention notice once per launch, recording `<launch>: terminal controls unavailable, direct attention` and reporting dialog counts as not observable. Handle a known `blocked` by the status contract. Without `send`, the user types the answer in the window. Under `--auto` the root decides and records the answer by [Deciding](../../child-sessions/references/auto.md#deciding) and gives the user that answer to type. Report missing `send` as a backend limitation. A timeout alone supplies no question or approval.

Check `alive` before supported input. Reopen only a proven dead launch under the shared budget below. Close only proven owned processes. Report retained windows when closure is unavailable. A retained shell alone takes no live-agent slot.

## Recovery and continuation

**Reopen.** While `Reopen: unused`, for a window `peek <name> 40`, show diagnostics, append “Continue from the current state of the checkout: read git log and record the ordinary Git evidence and verify checkout/branch/HEAD first.” to the retained brief, close the stale window if present and reopen once with the brief's recorded Launch settings and the record's `Launch words:`; never re-resolve them. For a dead-before-send reopen, also append the line meant to be sent to that brief before opening. Perform [Startup](../../child-sessions/SKILL.md#locate-and-open) and Window controls for the new opening, set `Reopen: used: <silent exit|dead before send>` and `State: accept: reopened`, and carry the reopen/reason to Report carries. This is the run's one reopen shared with Before every send. A second silent exit or dead-before-send when `Reopen: used` stops and reports with window, worktree and runtime files kept. Rewrite Waiting; a single root continues to Wait, Accept alone ends for the caller without waiting.

**Before every send.** For a blocked answer or return from Verify 1–3, End 2 or Merge 1, first ensure the old status is archived to an unused suffix (`<file>-blocked-<n>` for an answer, `<file>-returned-<n>` for a return), so the next wait sees only a fresh status. Then run `alive <name>`: a dead agent leaves a shell that would run the text. Dead: apply Reopen with the line meant to be sent, using the record's shared reopen budget; alive: send the line only if the launch supports send, else apply Brief's direct-attention rule. Never reopen a live agent to inject text.

**Return to the child.** Archive status to `<file>-returned-<n>`, write `Return to worker: used: <archived path>`, `Pending return:` with the reason below and `State: accept: returned to worker`. A Verify 1–3 return keeps an existing `Pending return: main moved to <sha>` unchanged until Merge 1 updates Base SHA; otherwise its reason is `verify mismatch`. Deliver the line through Before every send for a window. Outside window, a Verify 1–3 or End 2 return and Merge 1's main-moved or merge-candidate authorization continue the child as Wait continues a blocked answer: archive as above, then continue the same child with the line as the message, or the fresh child the run contract falls back to. For Accept alone, write `Action: continue <place>` with session/message and the full Waiting recipe instead; the caller continues it. Verify, End, Merge and Cleanup otherwise apply as written, except: each opening's settings evidence is what launch-settings' [child settings check](../../independent-review/references/launch-settings.md#child-settings-check) names; for background End 4's report adds each start's and resume's actual producer exit and session ID; Cleanup closes no window. Rewrite Waiting with Action none for a window or a continued worker. A single root continues to Wait; Accept alone ends as its brief says, naming the record, and waits for nothing. A return requiring Reopen retains the reopened state and shared budget.

On the fresh status, resume where `Pending return:` says: `verify mismatch` or `follow-ups correction` at Verify 1; `main moved to <sha>` at Merge 1's “verify a fresh report against that target, then update the recorded Base SHA”; `merge candidate <sha>` at Merge 1's “perform Verify and End again on the fresh report”. For a main-moved return, keep its target until Merge 1 updates the brief's Base SHA. For other returns, set `Pending return: none` only after Verify through step 3 passes on that report. Preserve a main-moved target as the reporting/review base until the brief's Base SHA is updated; do not verify that fresh report against the old base.
