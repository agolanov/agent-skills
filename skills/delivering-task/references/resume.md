# Resume delivery

This is Worktree step 3. Read the identity and compatibility rules during Preflight 2; apply the repair and archive only at Worktree 3, before opening.

3. For `--resume`, require the prior runtime brief whose identity block carries `Written by: delivering-task`. Any other brief stops before reopening, naming it: “brief written by a removed skill; finish that run with the catalog that started it, or remove its branch, worktree and runtime files by hand”. Require in it base, absolute task document/spec identity, branch, checkout, its `Place:` line, the window name for a `window` place, and its mode line, `Launch settings:`, `Reviewer settings:` and `Reviewer run:` lines. Match it to the requested task and registered Git worktree/branch; validate the recorded base exists and belongs to the task history. Reuse the recorded base/window identity, never today's main as a guessed replacement, and the recorded place, settings and `Reviewer run:` place, never re-resolved: an explicit flag equal to the recorded value is accepted, a different one stops; caller-resolved policy values never conflict, the recorded values win. A recorded `Reviewer run: subagent` cannot continue: ask for `background` or `window` before reopening (under `--auto`, routed by [auto.md](../../child-sessions/references/auto.md#deciding)) and write the answer into the brief's Reviewer run line. The recorded `Reviewer agent:` line is reused the same way, never re-resolved: an explicit key naming the recorded system (`--reviewer-agent X` for a recorded `X`, `--reviewer-dual` for a recorded `dual`, whatever the recorded source) is accepted, a different one stops, naming both values. A brief written before that line existed has none: read it as `<the system opposite to its Agent:> (default)` under the same rule; the line is not among those required above and is never inserted. The recorded `Implementation mode:` line is reused the same way, never decided again: an explicit `--impl` equal to it is accepted, a different one stops; a caller-decided mode never conflicts, the recorded mode wins. A brief written before the rename records the mode as `Execution mode:` with `inline` for `solo`; read it as `Implementation mode:` with `solo`. Outside `--run inline`, check the prior handoff record's `Launch words:` against the brief by [Authority](../../child-sessions/references/handoff-record.md#authority) 3. Missing, conflicting or ambiguous provenance stops, before any runtime file is archived or renamed. Preserve current work for the child; after those provenance, identity and Git continuation gates and before archiving status, read and perform [Resume repair](continuation.md#resume-repair). Then archive any prior status to an unused suffix and append “Continue from the current state of the checkout: read git log and record the ordinary Git evidence and verify checkout/branch/HEAD first.” An old terminal report cannot complete a resumed run.

   Outside `--run inline`, after these gates and Resume repair, rename an earlier handoff record to `<file>-old-<n>`, the smallest unused number, and create a new record with a new `Invocation: <time> resume`, its `Launch words:` the brief's value. Set `Reopen: unused`, `Return to worker: unused`, `Wait: not chosen`, `Pending return: none`; the resume's own open does not spend the reopen. Status archives and brief lines retained from before this Invocation are history, not contradictions of the reset Reopen and Return to worker lines; use the archived earlier record to distinguish them from this invocation's evidence. A new run uses `Invocation: <time> new`; a continuing phase resets none of these.
