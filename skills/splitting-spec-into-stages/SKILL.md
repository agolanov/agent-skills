# Splitting Spec Into Stages

For each clean/path gate and continuation below and in child briefs, use the four ordinary Git commands and identity checks in [checkout state](../independent-review/references/checkout-state.md#direct-use-preflight), with process-local `GIT_OPTIONAL_LOCKS=0`, actual exits and raw output files. These are own-paths gates over the spec in the repository holding it; unrelated staged or unstaged paths pass and stay untouched. A repository not holding the spec owns no path. A clean gate requires successful commands and empty status and diffs; path gates parse NUL-delimited status and compare exact repository-relative paths, including both rename paths. Failed or unavailable Git evidence stops the dependent action. Use ordinary Git for other read-only checks, retaining real exits. Evidence has the reference's ignored/untracked-content, Git flags/normalization, nested-repository and transient-write limits. Stage/commit only owned paths; write, merge and push authority stays explicit.


`splitting-spec-into-stages <spec> [--run window|inline|subagent|background] [--agent claude|codex] [--model M|cli-default] [--effort E|cli-default] [--auto]`

One spec per run. The splitter writes the spec's `## Stages` section, and `--run` places it ([Run](#run)). By default it is a child in a `window`, a visible session where it talks to the user, who answers its questions there, never through the root; a child in a `subagent` or `background` asks every question through the root; under `inline` this session is the splitter. The root classifies the spec, runs the splitter in the project checkout, waits, verifies Git/status facts and reports the stages. Outside `inline` it writes no document or mark, its one commit is Input 6's commit of the spec, and it never edits a child status. It invokes no other task skill: the user chooses what runs next. A stop placed "before any window" below comes, in every place, before the splitter starts.

Under `--auto` read child-sessions' [auto.md](../child-sessions/references/auto.md): the brief says `Auto: yes`, so the splitter asks nobody, in its window either, and each question it cannot settle by auto.md's [Deciding](../child-sessions/references/auto.md#deciding) step 1 reaches the root as `STATUS: blocked`; the root routes it and every question below that would go to the user by auto.md's Deciding, and the report lists `## Decisions`.

## Input

The project checkout is the top level of the current repository. When that top level is a separate docs repository (a `docs/superpowers` directory with its own repository), the project checkout is `git -C <docs-top>/../.. rev-parse --show-toplevel`; when that fails, ask the user for the project checkout (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)). Project-relative paths such as `**Spec:**` headers resolve against the project checkout, never the docs repository. Docs repository = `git -C <project>/docs/superpowers rev-parse --show-toplevel` when that directory exists, else the project checkout. Resolve the input; every stop happens before any window. An input naming no existing regular file (a missing path, a directory or other non-regular file, a task text) stops, naming it: "no such file; only an existing design spec is split into stages". Read the file completely and classify it by [task document paths](../planning-task-docs/references/document-paths.md), applying the first rule that matches:

1. **Plan**: a plan by task document paths. Refuse, naming it: "a plan, not a spec; only a design spec is split into stages".
2. **Spec**: a spec by task document paths. Run the spec checks below.
3. **Anything else** (a brief, a follow-ups file, any other file): refuse, naming it: "not a spec; only a design spec is split into stages".

Spec checks, in order:

1. `git -C <spec dir> rev-parse --show-toplevel` prints the docs repository; `<rel>` is the spec's path relative to it. Any other result stops, naming the spec's repository and the docs repository.
2. Locate the installed `planning-task-docs/references/stages-section.md` (the sibling [stages-section.md](../planning-task-docs/references/stages-section.md#recipes)) by absolute path. Missing: stop, naming `planning-task-docs` for the user to install. The brief's `Stage convention:` line names this path.
3. Run `stages_parse` from that file's Recipes on the spec, then follow its exit:
   - Exit 1 with stderr exactly `no "## Stages"`: the spec is unstaged; a `## Stages` line inside a fenced code block is no heading. Then check that a section appended at its end would be read: copy the spec to a temporary file outside Git, append the probe text `\n\n## Stages\n\n### Stage 01: Probe\n\n**Scope:** probe\n**Done when:** probe\n\n### Stage 02: Probe\n\n**Scope:** probe\n**Done when:** probe\n` (each `\n` one line feed), run `stages_parse` on the copy and remove it. Exit 0: continue. Exit 1: the spec ends inside a code fence that never closes (the Lines rule of the [display copy](references/stages-section.md#parsing-rules)), which would hide the appended section; stop: "the spec ends inside an unclosed code fence; close it and rerun". Exit 2: stop, reporting the stages evidence unavailable with the stderr reason.
   - Exit 2: stop, reporting the stages evidence unavailable with the stderr reason.
   - Any other exit (0, or exit 1 naming a broken section): the spec has a `## Stages` heading. Refuse: "already staged; edit the section by hand or run `delivering-spec-stages`".
4. Find its plans by task document paths, with no question, with or without a `**Stage:**` line. Any found: refuse, naming each plan: "already planned; splitting a spec whose work has started is a hand job".
5. No line of the spec matches `^Review: (clean|clean except disputed), `, except its last line when that line is a full review mark: the last line and mark pattern of [prefix-check.md](references/prefix-check.md#rule). The split keeps every other such line (a displaced stale mark, a malformed mark, a mark followed by an empty line, a quoted example) and Verify 8 rejects it, so stop, naming each such line by number and text: "a `Review:` line other than a final review mark; remove or reword it and rerun".
6. Commit the spec if it has uncommitted changes; checks 1-5 refuse first, so a refused run commits nothing. Preflight 2 runs before this commit, so its refusals commit nothing either. `<repo>` is the docs repository and `<rel>` the spec's path relative to it (check 1).
   - **Detect.** Take a fresh four-command boundary of `<repo>`; failed Git evidence stops, as at every gate. The spec has uncommitted changes (untracked, or tracked with staged or unstaged edits) when `<rel>` equals a path of the NUL-delimited status, either path of a rename or copy entry included.
   - **Commit.** With changes run `git -C '<repo>' --literal-pathspecs add -- '<rel>'`, then `git -C '<repo>' --literal-pathspecs commit -m 'docs: <basename>' -- '<rel>'`, and show `committed <rel> <sha7>`, with no question; without changes commit nothing. Each path and message is one literal shell argument, quoted for the shell that runs it (inside POSIX single quotes a single quote is written `'\''`; inside PowerShell single quotes it is doubled), and `--literal-pathspecs` keeps Git from reading a file name as pathspec magic. The pathspec commits the spec alone: other staged changes stay staged, unstaged and untracked paths stay as they are, and when the spec is one side of a staged rename only its own path is committed. A failing `add` or `commit` stops before any window, reporting Git's error.
   - **Confirm.** `git -C <repo> cat-file -e HEAD:<rel>` must exit 0: the spec is tracked at the docs repository's HEAD; any other exit is a Git problem and stops, reporting it.
   - **Order.** Preflight 1's own-paths gate runs after this commit, so it catches only a change made after it, and the docs HEAD it records is the one after the commit, so Verify 2's `<recorded HEAD>..HEAD` range does not contain the root's own commit.

`delivering-spec-stages/references/spec-checks.md` holds a display copy of this section from its first paragraph through spec check 3; keep them equal.

## Preflight

1. Resolve applicable project rules. Run the own-paths gate on the docs repository over the spec, `<rel>`. A hit stops, naming the path. Record the full HEAD of the docs repository and the spec's SHA-256.
2. Decide the place and the agent. This step runs before Input 6's commit (spec check 6), so its refusals commit nothing. The place is `--run`: `window` when absent, also under `--auto`, else `inline`, `subagent` or `background`; the user's words choosing a place count as the key, and any other value stops. Announce a place other than `window`. Select `--agent`, otherwise identify the root's own system from session identity as independent-review's [Session system](../independent-review/SKILL.md#session-system) does; unknown identity requires clarification (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)). Never infer the agent from executable availability, environment, directory names or model. Refuse before anything starts, naming the combination, what run contract [Refused combinations](../child-sessions/references/run-contract.md#refused-combinations) refuses for the splitter: under `inline`, an `--agent` naming a system other than this session's or an explicit `--model` or `--effort`, refused before any edit; under `subagent`, an `--agent` naming a system other than this session's, or this session being itself a subagent on a host whose subagents cannot start subagents.
3. Under `inline` resolve no settings: the splitter is this session ([launch settings Places](../independent-review/references/launch-settings.md#places)). Otherwise resolve the splitter's settings per [launch settings](../independent-review/references/launch-settings.md#precedence) for the selected agent: `--model`/`--effort` are explicit values, `cli-default` is a per-field [opt-out](../independent-review/references/launch-settings.md#cli-defaults-opt-out), and every other field takes the splitter role default. An unresolved or unsupported pair stops before any window. Under `subagent` and `background`, resolve and pass the pair as launch settings [Places](../independent-review/references/launch-settings.md#places) says for the place; a pair the place cannot select and verify is refused before launch, naming the place and the pair.
4. Locate the installed `child-sessions/SKILL.md`. Outside `inline` read it, its `references/brief-writing.md` and `references/status-file.md`, and under `subagent` and `background` its `references/run-contract.md`, which governs their launch, wait, questions and permissions. Resolve its installed platform entrypoint by absolute path (Bash `scripts/child-session`; native Windows `scripts/child-session.ps1` through the installed PowerShell vector in its platform reference). Its command/status contract governs every call. Set `<runtime>` from its successful `runtime-dir` output, outside Git; under `inline` it holds only the recorded file. The child needs no superpowers skill: its brief names the stage convention by absolute path.
5. `<spec-stem>` is the spec's [Spec stem](references/stages-section.md#parsing-rules), its file stem without `-design` (`specs/2026-11-03-plain-design.md` → `2026-11-03-plain`), with every character outside `[A-Za-z0-9_-]` replaced by `-`. Window `split-<spec-stem>`, brief `<runtime>/split-<spec-stem>-brief.md`, status `<runtime>/split-<spec-stem>-status.md`, recorded file `<runtime>/split-<spec-stem>-recorded.md`, and for `background` run directories `<runtime>/split-<spec-stem>-run-<n>`; under `inline` only the recorded file is used. A live window of that name (`alive split-<spec-stem>` returns 0) is refused, naming it. Leftover runtime files of that name from an earlier run (brief, status, recorded file, their archived `-blocked-<n>` and `-rejected-<n>` copies, and run directories) are renamed to `<file>-old-<n>`, `n` the smallest unused number, after the check of run contract [Earlier runs](../child-sessions/references/run-contract.md#earlier-runs); no earlier file remains at the brief, status or recorded path.
6. Last, copy the spec's working file byte for byte to the recorded file (an ordinary file copy, never `git show`, whose blob can differ from the working file) and check that the copy's SHA-256 equals the one recorded in step 1. A difference stops: the spec changed during Preflight.

## Brief

Outside `inline`, fill [splitter-brief.md](references/splitter-brief.md) with absolute resolved paths, the place of Preflight 2 and `Auto:` (`yes` under `--auto`), following child-sessions' brief checklist, and write it to the brief path. Its `Stage convention:` line is the absolute path located in Input.

A `window` brief's `Terminal controls:` line is the template's fixed text: the brief is written before `open`, when no launch exists to report a backend or controls. After every `open` (the first, a reopen, a resume), read that launch's `capabilities <name>` and check its checkout/launch identity before any terminal control; every `peek`, `send` and `key` below is conditional on the current launch's supported capability, never on the brief, and nothing about controls is written into the brief or sent to the child. When the current launch's record lacks `peek`, `send` or `key`, tell the user once for that launch that questions/dialogs need direct attention in that window, then continue through brief/status files; report dialog counts as not observable. A known `blocked` question still follows the status contract, with its answer entered directly by the user when `send` is unavailable. Under `--auto` the root still decides that answer by [auto.md](../child-sessions/references/auto.md#deciding) and records it; the user is asked only to type that given answer into the window, and the report names the missing `send` as the backend's limitation. A timeout alone supplies no question or approval. Check `alive` before any supported input; never reopen a live agent to inject text. Reopen a proven dead launch at most once under the shared budget below. `close` stops only proven owned processes; unavailable window closure leaves a reported retained window, whose shell alone is not a live agent.

## Run

Run the splitter in the place Preflight 2 decided.

### Window

1. Append the `Opened:` line of the [child settings check](../independent-review/references/launch-settings.md#child-settings-check) to the brief, then call `open --agent <agent> [--model M] [--effort E] --split right split-<spec-stem> <project checkout> <brief>`, quoting paths, passing the brief's recorded Launch settings as `--model` and `--effort` and omitting a field that is `cli-default`. The user answers the child's questions in its window (under `--auto`, only watches it), so it asks for a pane right of the root; when `open` prints a fallback note (a tab or a tmux window instead), tell the user where the window opened. The child works in the project checkout: no worktree, no branch of its own. Tell the user that the run owns the spec: leave it to the child while the window is open; any other file stays theirs to change and commit.
2. Follow child-sessions' [foreground wait loop](../child-sessions/SKILL.md#foreground-wait-loop) for `split-<spec-stem>`, using its host-specific duration, explicit tool timeout and same-command polling. Questions to the user can take long: keep waiting. At the first `wait` return after each `open`, run the early [child settings check](../independent-review/references/launch-settings.md#child-settings-check) for that opening and keep the matched record path; only a mismatch stops the loop for the user's continue-or-stop question (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)).
3. On exit `0`, read the exact first status line. `done` proceeds to Verify. `blocked` shows Questions, options and recommendation, obtains the user's answer (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding); without `send` the user only types it in, as Brief says), archives the status to `<file>-blocked-<n>`, sends one line or an absolute answer-file instruction, then waits for a fresh status. `failed` shows the failure and stops, keeping the window and status; the report says the spec was not split and lists any commits the status names.
4. Exit `3`: `peek split-<spec-stem> 40`, show diagnostics, append “Continue from the current state of the checkout: read git log and record the ordinary Git evidence and verify checkout/branch/HEAD first. Uncommitted changes on your owned paths are your earlier session's work: inspect them and continue from them.” to the brief, close the stale window if present, append a new `Opened:` line and reopen once with the brief's recorded Launch settings; never re-resolve them. A second silent exit stops, keeping the window and status. Exit `124`: `peek split-<spec-stem> 40`; wait again for work in progress, or handle a dialog per child-sessions Dialogs. Other errors stop with artifacts preserved.
5. Before every `send` (a `blocked` answer here, a mismatch line in Verify), run `alive split-<spec-stem>`: a dead agent leaves a shell that would run the text. Dead: `close split-<spec-stem>`, append the continuation line of step 4 and then the line you meant to send to the brief, append a new `Opened:` line, and `open` again with the brief's recorded Launch settings, never re-resolved; this is the run's one reopen, shared with step 4. When that reopen was already used, stop and report, keeping the window and runtime files.

### Subagent and background

1. Append the `Opened:` line of the [child settings check](../independent-review/references/launch-settings.md#child-settings-check) to the brief, then start the splitter in the project checkout by run contract [Launch and wait](../child-sessions/references/run-contract.md#launch-and-wait): a `subagent` with the pair Preflight 3 resolved, set by the host's native controls; a `background` CLI with the brief's recorded Launch settings, omitting a field that is `cli-default`, and the permission arguments of run contract [Permissions](../child-sessions/references/run-contract.md#permissions), since the splitter writes and commits. Each `background` start or resume writes its run directory at `<runtime>/split-<spec-stem>-run-<n>`, `n` the smallest unused number. Tell the user that the run owns the spec until it reports, as Window step 1 words it. The child works in the project checkout: no worktree, no branch of its own.
2. Wait as that section says. At the first status after each opening, run the early child settings check for that opening as launch settings [Places](../independent-review/references/launch-settings.md#places) says; only a mismatch stops for the user's continue-or-stop question (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)).
3. Read the exact first status line. `done` proceeds to Verify. `blocked`: show the user the Questions section verbatim, with its options and recommendation, and obtain the user's answer (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)); archive the status to `<file>-blocked-<n>`; continue the same child with the answer by run contract [Questions and continuation](../child-sessions/references/run-contract.md#questions-and-continuation), or the fresh child it falls back to, which gets a new `Opened:` line; then wait again. `failed` shows the failure and stops, keeping the status, recorded file and run directories; the report says the spec was not split and lists any commits the status names.
4. A child that ends without a valid first status line gets the run contract's one restart; a second such end, or a launch failure, stops as that section says, keeping the checkout, status, recorded file and run directories.
5. Verify and Report apply as written, except: a mismatch Verify returns to the child is archived as Verify says, then continues the same child as step 3 does, its one line being the message; each opening's settings record is the one launch settings [Places](../independent-review/references/launch-settings.md#places) names for the place; for `background` the report adds each start's and resume's producer exit and session ID; there is no window to close, and a verified `done` still removes the recorded file.

### Inline

This session is the splitter: no child, brief, status file or window.

1. Tell the user that the run owns the spec until it reports, as Window step 1 words it. Perform the Work of [splitter-brief.md](references/splitter-brief.md), with the Stage convention file Input located and the brief's rules after Work: Boundaries and out-of-scope findings. Work in the project checkout and talk to the user directly in this session, asking only where a boundary cannot be derived from the spec and the code; under `--auto` such a question is routed by [auto.md](../child-sessions/references/auto.md#deciding) instead. Where the brief says to write STATUS: blocked, stop and report that to the user. Note each stage larger than criterion 2's guideline, with its reason, for the report.
2. Verify 2–8 hold with the spec as the Artifacts path and this session's own commits as Commits; Verify 1, the status format, and Verify 9, the settings check, do not apply. Exit 2 of `prefix_check` or `stages_parse` stops as Verify says. Correct a mismatch of your own once and verify again; a user commit changing the spec goes to the user per Verify 2, and so does a repeated mismatch.
3. Report as Report says, the larger stages being those of step 1; after a verified run remove the recorded file, with no window to close. The settings line says `inline: current session` and names this session's system.

## Verify

On `done`, all of these must hold:

1. Full status format with `## Artifacts`, listing exactly the spec, by its absolute path.
2. Commits lists the child's own commits in the docs repository: each is in `<recorded HEAD>..HEAD` and changes only the spec (`git show --name-only --format= --no-renames <sha>`, relative to the docs repository). Every other commit of that range is the user's parallel work and leaves the spec unchanged; one that changes it stops Verify and goes to the user, naming the commit, never back to the child.
3. A fresh own-paths gate on the docs repository over the spec passes: the split is not left uncommitted.
4. The recorded file's SHA-256 still equals the recorded one. A difference is unavailable evidence: stop, keeping the window and status.
5. [prefix-check.md](references/prefix-check.md) returns 0, with `file` the spec and `recorded` the recorded file: the section was appended and at most a trailing `Review:` mark removed, nothing else changed.
6. `stages_parse` returns 0 on the spec.
7. The `## Stages` section holds a line starting `**Coverage:** ` after its last stage heading, as the Coverage rule of the [display copy](references/stages-section.md#parsing-rules) requires of a section this skill wrote.
8. No line of the spec matches `^Review: (clean|clean except disputed), `.
9. The final [child settings check](../independent-review/references/launch-settings.md#child-settings-check) over every opening's record matches, or the user accepted its result.

Exit 2 of `prefix_check` or `stages_parse` is unavailable evidence too: stop, keeping the window and status. A settings mismatch or `settings unverified: <reason>` never goes back to the child: show expected and observed values and the record paths, and ask the user to accept the result with the observed settings or stop with everything preserved (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)). A user commit changing the spec goes to the user per Verify 2. Any other mismatch goes back to the child once: archive the status to `<file>-rejected-<n>`, `n` the smallest unused number, `send` one line naming the mismatch and asking for a fresh report at the same path, wait and verify again. A repeated mismatch goes to the user, with window and status kept.

## Report

Report the spec path, its stages as `stages_parse` lists them (number and name, each with the first sentence of its `**Scope:**`), the repository and commits that hold the split, the Input 6 commit of the spec (`committed <rel> <sha7>`) when one was made, every stage the child reported larger than the guideline with its reason (its Checks lines), and every Out of scope line. When Verify 3's preflight listed paths other than the spec, add `unrelated uncommitted changes left untouched: <count>`, without listing them. Add one settings line: role `splitter`, effective model and effort, source of each, the settings check outcome, and the record paths or the user's acceptance. Under `--auto` add the `## Decisions` of [auto.md](../child-sessions/references/auto.md#decisions): the root's own and those of the child's status. After a verified `done`, `close split-<spec-stem>` and remove the recorded file; otherwise the window, status and recorded file stay for the user. Nothing is reviewed, planned or executed here: the next step is `refining-task-docs <spec>`, then `delivering-spec-stages <spec>`.
