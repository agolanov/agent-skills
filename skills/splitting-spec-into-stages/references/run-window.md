# Run in a window

A `window` brief's `Terminal controls:` line is the template's fixed text: the brief is written before `open`, when no launch exists to report a backend or controls. After every `open` (the first, a reopen, a resume), read that launch's `capabilities <name>` and check its checkout/launch identity before any terminal control; every `peek`, `send` and `key` below is conditional on the current launch's supported capability, never on the brief, and nothing about controls is written into the brief or sent to the child. When the current launch's record lacks `peek`, `send` or `key`, tell the user once for that launch that questions/dialogs need direct attention in that window, then continue through brief/status files; report dialog counts as not observable. A known `blocked` question still follows the status contract, with its answer entered directly by the user when `send` is unavailable. Under `--auto` the root still decides that answer by [auto.md](../../child-sessions/references/auto.md#deciding) and records it; the user is asked only to type that given answer into the window, and the report names the missing `send` as the backend's limitation. A timeout alone supplies no question or approval. Check `alive` before any supported input; never reopen a live agent to inject text. Reopen a proven dead launch at most once under the shared budget below. `close` stops only proven owned processes; unavailable window closure leaves a reported retained window, whose shell alone is not a live agent.

1. Use the [window launch sequence](../../child-sessions/SKILL.md#locate-and-open) with `open --agent <agent> [--model M] [--effort E] [--cli-arg WORD]... --split right split-<spec-stem> <project checkout> <brief>`, quoting paths, passing the brief's recorded Launch settings as `--model` and `--effort` and omitting a field that is `cli-default`, and for a Claude agent the run contract's [lean launch](../../child-sessions/references/run-contract.md#launch-and-wait) words as `--cli-arg` values. Keep these words and pass the same words on every reopen, a `--session-id` word with a fresh UUID. The user answers the child's questions in its window (under `--auto`, only watches it), so it asks for a pane right of the root; when `open` prints a fallback note (a tab or a tmux window instead), tell the user where the window opened.
2. Handle the Startup result, then follow child-sessions' [Wait](../../child-sessions/SKILL.md#wait) for `split-<spec-stem>`, using the rung it proves or its present loop with the host-specific duration, explicit tool timeout and same-command polling. Questions to the user can take long: keep waiting; on a free rung each quiet stretch costs one stall wake.
3. Exit `0` dispatches the exact first status line by [Run](../SKILL.md#run). For a block, send the answer in one line or as an absolute answer-file instruction. Without `send` the user enters it as above. Keep the window on failure.
4. Exit `3`: `peek split-<spec-stem> 40`, show diagnostics, append “Continue from the current state of the checkout: read git log and record the ordinary Git evidence and verify checkout/branch/HEAD first. Uncommitted changes on your owned paths are your earlier session's work: inspect them and continue from them.” to the brief, close the stale window if present and reopen once with the brief's recorded Launch settings and the kept launch words (step 1); never re-resolve them. A second silent exit stops, keeping the window and status. Exit `124`: `peek split-<spec-stem> 40`; wait again for work in progress, or handle a dialog per child-sessions Dialogs. Other errors stop with artifacts preserved.
5. Before every `send` (a `blocked` answer here, a mismatch line in Verify), run `alive split-<spec-stem>`: a dead agent leaves a shell that would run the text. Dead: `close split-<spec-stem>`, append the continuation line of step 4 and then the line you meant to send to the brief, and `open` again with the brief's recorded Launch settings, never re-resolved; this is the run's one reopen, shared with step 4. When that reopen was already used, stop and report, keeping the window and runtime files.
