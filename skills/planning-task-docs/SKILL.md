# Planning Task Docs

For each clean/path gate and continuation below and in child briefs, use the four ordinary Git commands and identity checks in [checkout state](../independent-review/references/checkout-state.md#direct-use-preflight), with process-local `GIT_OPTIONAL_LOCKS=0`, actual exits and raw output files. These are own-paths gates over the spec and plan in the repository holding them; unrelated staged or unstaged paths pass and stay untouched. A repository holding neither document owns no path. A clean gate requires successful commands and empty status and diffs; path gates parse NUL-delimited status and compare exact repository-relative paths, including both rename paths. Failed or unavailable Git evidence stops the dependent action. Use ordinary Git for other read-only checks, retaining real exits. Evidence has the reference's ignored/untracked-content, Git flags/normalization, nested-repository and transient-write limits. Stage/commit only owned paths; write, merge and push authority stays explicit.


`planning-task-docs <"task text"|brief|spec|follow-ups file> [--run window|inline|subagent|background] [--agent claude|codex] [--model M|cli-default] [--effort E|cli-default] [--auto]`

One task per run. The planner writes the documents with superpowers `brainstorming` and `writing-plans`, and `--run` places it ([Run](#run)). By default it is a child in a `window`, a visible session where it talks to the user, who answers its questions there, never through the root; a child in a `subagent` or `background` asks every question through the root; under `inline` this session is the planner. The root classifies the input, runs the planner in the project checkout, waits, verifies Git/status facts and reports paths. Outside `inline` it writes no document, mark or commit and never edits a child status. It invokes no other task skill: the user chooses what runs next. A stop placed "before any window" below comes, in every place, before the planner starts.

Under `--auto` read child-sessions' [auto.md](../child-sessions/references/auto.md): the brief says `Auto: yes`, so the planner asks nobody, in its window either, and each question it cannot settle by auto.md's [Deciding](../child-sessions/references/auto.md#deciding) step 1, brainstorming's and the spec's approval included, reaches the root as `STATUS: blocked`; the root routes it and every question below that would go to the user by auto.md's Deciding, and the report lists `## Decisions`.

## Input

The project checkout is the top level of the current repository. When that top level is a separate docs repository (a `docs/superpowers` directory with its own repository), the project checkout is `git -C <docs-top>/../.. rev-parse --show-toplevel`; when that fails, ask the user for the project checkout (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)). Project-relative paths such as `**Spec:**` headers resolve against the project checkout, never the docs repository. Resolve the input; read a given file completely. Classify it by the first rule that matches; every stop happens before any window:

1. **Follow-ups file**: a file whose name ends `-follow-ups.md`, or `-tails.md` (the older format of the same file). Each line starting with `- ` is one finding. With none, report "nothing to plan" and stop.
2. **Plan**: it carries the superpowers plan header (`> **For agentic workers:** REQUIRED SUB-SKILL:`) or lies in a `plans/` directory of a superpowers docs dir (`docs/superpowers/plans/`). Refuse: "already planned; review it with `refining-task-docs` or execute it with `delivering-task`".
3. **Spec**: named `*-design.md` or lying in a `specs/` directory. Run `stages_parse` from [references/stages-section.md](references/stages-section.md#recipes) on it, then follow its exit:
   - Exit 1 with stderr exactly `no "## Stages"`: the spec is unstaged. Find its plans in the sibling `plans/` directory, with no question: the naming pair (`specs/YYYY-MM-DD-<slug>-design.md` with `plans/YYYY-MM-DD-<slug>.md`), and every plan whose `**Spec:**` header (path relative to the project checkout) names this spec. Any found: report "already planned", naming each plan, with the same pointer to `refining-task-docs` or `delivering-task`, and stop. None: the child writes the plan only.
   - Any other exit 1: the spec's `## Stages` section is broken. Stop, naming the failed rule: the stderr line and the Parsing rule that words it. Exit 2: stop, reporting the stages evidence unavailable with the stderr reason.
   - Exit 0: the spec is staged; stdout lists its stages. Apply the Parsing rules of [stages-section.md](references/stages-section.md#parsing-rules) to the sibling `plans/` directory, with no question. The spec's plans are the candidates (follow-ups and tails files excluded) that are the naming pair, carry a `**Spec:**` header naming this spec, or have a stem starting with `<spec-stem>-NN-` for a stage NN of the section and belong to no other spec, as Stage matching says: a plan found only by its file name counts. Then apply, in order: Stage matching, which stops on a plan matching two stages, naming it and both stages, and on two plans matching one stage, naming both; Unstaged plan, where an unstaged plan stops, naming it: "staged spec with an unstaged plan; remove or stage the plan"; Next stage. With no next stage, every stage is planned: report "already planned", naming each stage plan, with the same pointer to `refining-task-docs` or `delivering-task`, and stop. When the next stage's Stage plan path already exists, stop before any window, naming the stage and the path: "stage NN's plan path holds another spec's plan; rename the stage or that plan". Else the child writes the next stage's plan only, at its Stage plan path.
4. **Brief**: any other existing file.
5. **Task text**: a quoted text that is not an existing path.

`<slug>` is the input file's stem; for a staged spec, `<slug>` is `<spec-stem>-<NN>-<stage-slug>` of the next stage (window `plan-<slug>`); for a task text, `<today>-<slug>` with `<slug>` made of `[a-z0-9-]` from its key words (`Add a --version flag` → `2026-11-01-version-flag`). Replace every character outside `[A-Za-z0-9_-]` with `-`.

## Preflight

1. Resolve applicable project rules and the project checkout. Define absolute `docs_dir` as the rules' documentation destination, defaulting to `<project>/docs/superpowers` even when absent. Derive the intended absolute output paths before any repository-relative conversion: for a spec input, only the plan of its naming pair in the sibling `plans/` directory, or the next stage's exact Stage plan path (Input rule 3); for other inputs whose `<slug>` starts with `YYYY-MM-DD-`, `<docs_dir>/specs/<slug>-design.md` and `<docs_dir>/plans/<slug>.md`. For remaining inputs, resolve the intended spec and plan names under `<docs_dir>/specs/` and `<docs_dir>/plans/` from the actual input and project rules, preserving brainstorming's and writing-plans' existing naming conventions; bind those absolute paths before proceeding to the gates. The input spec remains read only. Keep Input's existing plan and stage-path collision stops.
2. Locate and read the installed `child-sessions/SKILL.md`. Resolve its installed platform entrypoint by absolute path (Bash `scripts/child-session`; native Windows `scripts/child-session.ps1` through the installed PowerShell vector in its platform reference). Its command/status contract governs every call. Set absolute `<runtime>` from successful `runtime-dir` output; unavailable resolution stops dependent preparation. Do this under `inline` too, for evidence storage only: resolve no terminal backend or launch settings there.
3. Allocate a fresh uniquely named evidence directory under `<runtime>`, with separate `root/` and `child/` subdirectories; bind their absolute paths now. Keep it outside every monitored project and document repository, confirming the document repository in step 4 before captures. Every root Git boundary gets a fresh named directory below `root/`; the child's boundaries go below `child/`. Keep this evidence separate from background producer run directories, retain older evidence, and never reuse or rename another run's evidence. Runtime-only preparation may precede later place/settings refusals: it launches no worker or backend and creates no project document.
4. Resolve the document repository: when `docs_dir` exists, require successful `git -C <docs_dir> rev-parse --show-toplevel`; when absent, use the project repository without creating `docs_dir` to classify the run. Allow the project repository, or a separate repository rooted at the existing docs destination; another destination/repository requires explicit applicable project-rule authority. Require every intended absolute output inside that authorized repository and convert it to its exact repository-relative owned path; refuse any other mapping rather than guessing. A separate repository at `<project>/docs/superpowers` owns `specs/2026-11-05-sample-design.md`; tracked or absent `<project>/docs/superpowers` in the project repository owns `docs/superpowers/specs/2026-11-05-sample-design.md` (and the corresponding `plans/` path). For each output run `git -C <selected-repository> check-ignore --quiet -- <exact-relative-path>`, retaining actual exits and outputs below the root evidence directory: 0 means ignored, 1 unignored, any other exit unavailable. Ignored or unavailable output checks stop before any worker launch or document write, inline included; for ignored output ask for an authorized trackable destination or separate docs repository. Do not force-add, initialize a repository or change ignores.
5. With fresh boundary directories below the root evidence directory, verify checkout/branch/HEAD identity and run the four-command own-paths gates on the repositories holding the intended documents, using only those exact relative output paths. A hit stops, naming the path; unrelated staged or unstaged work passes and stays untouched. Record the full HEAD of the docs repository and, when separate, the project checkout. For a brief, spec or follow-ups input, record the input file's SHA-256.
6. Decide the place and the agent. The place is `--run`: `window` when absent, also under `--auto`, else `inline`, `subagent` or `background`; the user's words choosing a place count as the key, and any other value stops. Announce a place other than `window`. Select `--agent`, otherwise identify the root's own system from session identity as independent-review's [Session system](../independent-review/SKILL.md#session-system) does; unknown identity requires clarification (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)). Never infer the agent from executable availability, environment, directory names or model. Refuse before any worker launch or document edit, naming the combination, what run contract [Refused combinations](../child-sessions/references/run-contract.md#refused-combinations) refuses for the planner: under `inline`, an `--agent` naming a system other than this session's or an explicit `--model` or `--effort`; under `subagent`, an `--agent` naming a system other than this session's, or this session being itself a subagent on a host whose subagents cannot start subagents.
7. Under `inline` resolve no settings: the planner is this session ([launch settings Places](../independent-review/references/launch-settings.md#places)). Otherwise read child-sessions' `references/brief-writing.md` and `references/status-file.md`, and under `subagent` and `background` its `references/run-contract.md`, which governs their launch, wait, questions and permissions. Resolve the planner's settings per [launch settings](../independent-review/references/launch-settings.md#precedence) for the selected agent: `--model`/`--effort` are explicit values, `cli-default` is a per-field [opt-out](../independent-review/references/launch-settings.md#cli-defaults-opt-out), and every other field takes the planner role default. An unresolved or unsupported pair stops before any window. Under `subagent` and `background`, resolve and pass the pair as launch settings [Places](../independent-review/references/launch-settings.md#places) says for the place; a pair the place cannot select and verify is refused before launch, naming the place and the pair.
8. Check the selected child's actual installed catalogs, this session's own under `inline` (Claude: `~/.claude/skills`, enabled `~/.claude/plugins`; Codex: `~/.codex/skills`, `~/.agents/skills`, enabled `~/.codex/plugins`; plus the project's `.claude/skills` and `.agents/skills`). Resolve readable absolute SKILL.md paths for superpowers `brainstorming` (not needed for a spec input) and `writing-plans`. Executables or the root's catalog alone do not prove child skill availability. A missing one stops before any window: ask the user to install superpowers for that agent. No other skill substitutes for them.
9. Outside `inline`: window `plan-<slug>`, brief `<runtime>/plan-<slug>-brief.md`, status `<runtime>/plan-<slug>-status.md`, and for `background` run directories `<runtime>/plan-<slug>-run-<n>`. A live window of that name (`alive plan-<slug>` returns 0) is refused, naming it. Leftover runtime files of that name from an earlier run (brief, status, their archived `-blocked-<n>` and `-rejected-<n>` copies, and run directories) are renamed to `<file>-old-<n>`, `n` the smallest unused number, after the check of run contract [Earlier runs](../child-sessions/references/run-contract.md#earlier-runs); no file exists at the status path when the brief is written. Evidence directories are retained separately and excluded from this renaming.

## Brief

Outside `inline`, fill [planner-brief.md](references/planner-brief.md) with absolute resolved document paths and the child evidence directory bound in Preflight 3, the place of Preflight 6 and `Auto:` (`yes` under `--auto`), following child-sessions' brief checklist, and write it to the brief path. Substitute every labelled field, including `Authority:` and `Git evidence directory:`; narrow Authority and Ownership to the actual outputs (plan only for a spec input), keeping any input spec read only. Work, Authority, Ownership and Boundaries must agree.

A `window` brief's `Terminal controls:` line is the template's fixed text: the brief is written before `open`, when no launch exists to report a backend or controls. After every `open` (the first, a reopen, a resume), read that launch's `capabilities <name>` and check its checkout/launch identity before any terminal control; every `peek`, `send` and `key` below is conditional on the current launch's supported capability, never on the brief, and nothing about controls is written into the brief or sent to the child. When the current launch's record lacks `peek`, `send` or `key`, tell the user once for that launch that questions/dialogs need direct attention in that window, then continue through brief/status files; report dialog counts as not observable. A known `blocked` question still follows the status contract, with its answer entered directly by the user when `send` is unavailable. Under `--auto` the root still decides that answer by [auto.md](../child-sessions/references/auto.md#deciding) and records it; the user is asked only to type that given answer into the window, and the report names the missing `send` as the backend's limitation. A timeout alone supplies no question or approval. Check `alive` before any supported input; never reopen a live agent to inject text. Reopen a proven dead launch at most once under the shared budget below. `close` stops only proven owned processes; unavailable window closure leaves a reported retained window, whose shell alone is not a live agent.

## Run

Run the planner in the place Preflight 6 decided.

### Window

1. Append the `Opened:` line of the [child settings check](../independent-review/references/launch-settings.md#child-settings-check) to the brief, then call `open --agent <agent> [--model M] [--effort E] --split right plan-<slug> <project checkout> <brief>`, quoting paths, passing the brief's recorded Launch settings as `--model` and `--effort` and omitting a field that is `cli-default`. The user answers the child's questions in its window (under `--auto`, only watches it), so it asks for a pane right of the root; when `open` prints a fallback note (a tab or a tmux window instead), tell the user where the window opened. The child works in the project checkout: no worktree, no branch of its own. Tell the user that the run owns the task's documents: edit neither the input file nor the spec and plan being written while the window is open; any other file stays theirs to change and commit.
2. Follow child-sessions' [foreground wait loop](../child-sessions/SKILL.md#foreground-wait-loop) for `plan-<slug>`, using its host-specific duration, explicit tool timeout and same-command polling. Brainstorming with the user can take long: keep waiting. At the first `wait` return after each `open`, run the early [child settings check](../independent-review/references/launch-settings.md#child-settings-check) for that opening and keep the matched record path; only a mismatch stops the loop for the user's continue-or-stop question (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)).
3. On exit `0`, read the exact first status line. `done` proceeds to Verify. `blocked` shows Questions, options and recommendation, obtains the user's answer (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding); without `send` the user only types it in, as Brief says), archives the status to `<file>-blocked-<n>`, sends one line or an absolute answer-file instruction, then waits for a fresh status. `failed` shows the failure and stops, keeping the window and status; the report says no spec and plan were produced and lists any commits the status names.
4. Exit `3`: `peek plan-<slug> 40`, show diagnostics, append “Continue from the current state of the checkout: read git log and record the ordinary Git evidence and verify checkout/branch/HEAD first. Uncommitted changes on your owned paths are your earlier session's work: inspect them and continue from them.” to the brief, close the stale window if present, append a new `Opened:` line and reopen once with the brief's recorded Launch settings; never re-resolve them. A second silent exit stops, keeping the window and status. Exit `124`: `peek plan-<slug> 40`; wait again for work in progress, or handle a dialog per child-sessions Dialogs. Other errors stop with artifacts preserved.
5. Before every `send` (a `blocked` answer here, a mismatch line in Verify), run `alive plan-<slug>`: a dead agent leaves a shell that would run the text. Dead: `close plan-<slug>`, append the continuation line of step 4 and then the line you meant to send to the brief, append a new `Opened:` line, and `open` again with the brief's recorded Launch settings, never re-resolved; this is the run's one reopen, shared with step 4. When that reopen was already used, stop and report, keeping the window and runtime files.

### Subagent and background

1. Append the `Opened:` line of the [child settings check](../independent-review/references/launch-settings.md#child-settings-check) to the brief, then start the planner in the project checkout by run contract [Launch and wait](../child-sessions/references/run-contract.md#launch-and-wait): a `subagent` with the pair Preflight 7 resolved, set by the host's native controls; a `background` CLI with the brief's recorded Launch settings, omitting a field that is `cli-default`, and the permission arguments of run contract [Permissions](../child-sessions/references/run-contract.md#permissions), since the planner writes and commits. Each `background` start or resume writes its run directory at `<runtime>/plan-<slug>-run-<n>`, `n` the smallest unused number. Tell the user that the run owns the task's documents until it reports, as Window step 1 words it. The child works in the project checkout: no worktree, no branch of its own.
2. Wait as that section says. At the first status after each opening, run the early child settings check for that opening as launch settings [Places](../independent-review/references/launch-settings.md#places) says; only a mismatch stops for the user's continue-or-stop question (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)).
3. Read the exact first status line. `done` proceeds to Verify. `blocked`: show the user the Questions section verbatim, with its options and recommendation, and obtain the user's answer (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)); archive the status to `<file>-blocked-<n>`; continue the same child with the answer by run contract [Questions and continuation](../child-sessions/references/run-contract.md#questions-and-continuation), or the fresh child it falls back to, which gets a new `Opened:` line; then wait again. `failed` shows the failure and stops, keeping the status and run directories; the report says no spec and plan were produced and lists any commits the status names.
4. A child that ends without a valid first status line gets the run contract's one restart; a second such end, or a launch failure, stops as that section says, keeping the checkout, status and run directories.
5. Verify and Report apply as written, except: a mismatch Verify returns to the child is archived as Verify says, then continues the same child as step 3 does, its one line being the message; each opening's settings record is the one launch settings [Places](../independent-review/references/launch-settings.md#places) names for the place; for `background` the report adds each start's and resume's producer exit and session ID; there is no window to close.

### Inline

This session is the planner: no child, brief, status file or window.

1. Tell the user that the run owns the task's documents until it reports, as Window step 1 words it. Use Preflight 1–5's resolved document paths, repository-relative owned paths and root evidence directory for every ordinary Git gate and capture. Read the brainstorming and writing-plans SKILL.md paths Preflight 8 resolved, then perform the Work of [planner-brief.md](references/planner-brief.md) for the input Input classified, with the values the brief's lines would carry (for a staged spec its Stage, Plan path and Earlier stages lines) and every rule of the brief after Work except the status contract and the Talking to the user paragraphs. Work in the project checkout and talk to the user directly in this session: brainstorming keeps its approval of the spec before writing-plans, and a follow-ups file's selection is asked here; under `--auto` these questions are routed by [auto.md](../child-sessions/references/auto.md#deciding) instead. Where the brief says to write STATUS: blocked or failed, stop and report that to the user.
2. Verify 1–5 hold with the documents this session wrote as Artifacts and its own commits as Commits, Verify 1's status format aside; Verify 6, the settings check, does not apply. Correct a mismatch of your own once and verify again; a user commit changing an Artifacts path goes to the user per Verify 2, and so does a repeated mismatch.
3. Report as Report says, with no window to close; the settings line says `inline: current session` and names this session's system.

## Verify

On `done`, all of these must hold:

1. Full status format with `## Artifacts`, listing the spec and plan written (only the plan for a spec input); every Artifacts path exists. For a staged spec, the Artifacts plan is at `Plan path:` and holds the line `**Stage:** NN` of the next stage.
2. The repository holding the documents (`git -C <document-dir> rev-parse --show-toplevel`) is the authorized repository resolved in Preflight 4, and the Artifacts paths are the intended outputs. Commits lists the child's own commits there: each is in `<recorded HEAD>..HEAD` and changes only Artifacts paths (`git show --name-only --format= --no-renames <sha>`, relative to that repository). Every other commit of that range is the user's parallel work and changes no Artifacts path; one that does stops Verify and goes to the user, naming the commit, never back to the child. The other repository's HEAD may move freely.
3. A fresh own-paths gate on that repository over the Artifacts paths passes: no document of the run is left uncommitted.
4. No Artifacts document ends with a line matching `^Review: `.
5. For a brief, spec or follow-ups input, the input file's SHA-256 equals the recorded one.
6. The final [child settings check](../independent-review/references/launch-settings.md#child-settings-check) over every opening's record matches, or the user accepted its result.

A settings mismatch or `settings unverified: <reason>` never goes back to the child: show expected and observed values and the record paths, and ask the user to accept the result with the observed settings or stop with everything preserved (under `--auto`, routed by [auto.md](../child-sessions/references/auto.md#deciding)). A user commit changing an Artifacts path goes to the user per Verify 2. Any other mismatch goes back to the child once: archive the status to `<file>-rejected-<n>`, `send` one line naming the mismatch and asking for a fresh report at the same path, wait and verify again. A repeated mismatch goes to the user, with window and status kept.

## Report

Report the spec and plan paths, for a staged spec the stage number and name, the repository and commits that hold them, and every Out of scope line. Name the root and child Git evidence directories, only the root directory under `inline`; evidence is separate from document Artifacts and background producer records. When Verify 3's preflight listed paths other than the Artifacts paths, add `unrelated uncommitted changes left untouched: <count>`, without listing them. Add one settings line: role `planner`, effective model and effort, source of each, the settings check outcome, and the record paths or the user's acceptance. Under `--auto` add the `## Decisions` of [auto.md](../child-sessions/references/auto.md#decisions): the root's own and those of the child's status. After a verified `done`, `close plan-<slug>`; otherwise the window and status stay for the user. Nothing is merged, reviewed or executed here: review is `refining-task-docs`, execution `delivering-task`.
